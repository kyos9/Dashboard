# 신호판 대시보드

`SIGNAL_APP_SPEC.md`의 무릎매수(v2)/어깨매도(참고) 시그널 로직을 기반으로, 종목을 자유롭게
추가·변경·제거하면서 현재 시그널 상태와 히스토리, 리밸런싱 상태를 확인하는 개인용 참고 대시보드.

화면에는 스펙의 이름 대신 **매수 시그널 / 매도 시그널**로 적습니다. 조건이 여러 갈래여도
사람이 볼 때 알아야 하는 건 결국 사라는 건지 팔라는 건지이기 때문입니다. 코드와 API의
필드 이름(`knee_buy_v2`, `shoulder_sell_ref`)은 스펙과 1:1로 맞춰 그대로 둡니다.

## 구조

- `backend/` — FastAPI + SQLite. 지표 계산, 시그널 판정, 매수 워크플로우, 리밸런싱/비중조절 신호, yfinance 데이터 수집.
- `frontend/` — Vite + React + TypeScript. 대시보드/히스토리 차트/리밸런싱/종목 관리 4개 화면.

## 화면 구성

- **대시보드** — 상단 요약 카드(신호등 현황 / 이번 기간 매수 / 비중조절 신호 / 포트폴리오 배분),
  구분·신호 필터 칩, 그리고 종목별 시그널 매트릭스. 각 지표에 해석 문구가 붙고, **매수 조건은
  그 조건이 나온 지표 칸에** ✓로 붙습니다 (DI 약세는 DI 칸에, ADX > 20은 ADX 칸에). 조건을
  한곳에 모아두면 어느 숫자에서 나온 말인지 눈으로 이을 수 없기 때문입니다.
  종목 이름은 국내는 **종목명**, 해외는 **티커**로 적고, 누르면 **차트가 팝업으로** 뜹니다 —
  보던 표의 스크롤과 필터를 잃지 않습니다.
  좁은 화면에서는 카드 보기로 자동 전환되며 상단에서 직접 전환할 수도 있습니다.
  맨 앞의 **⠿를 끌어서** 순서를 바꾸고(키보드는 ↑↓), 상단 **설정**을 누르면 보던 표가 그대로
  입력칸으로 바뀌어 여러 종목을 고친 뒤 한 번에 저장합니다. 순서는 저장되어 리밸런싱·히스토리
  화면에도 그대로 적용됩니다.
- **히스토리 차트** — 로그 스케일 종가 차트 + 매수 실행일/매도 시그널 마커. 매도 시그널은 연속
  발동 구간을 하나로 묶어 표시해 라벨이 겹치지 않습니다.
- **리밸런싱** — 목표 비중과 현재 비중의 차이를 **금액과 예상 주문 주수**로 환산한 주문 가이드.
  총 운용자산을 직접 입력하면(현금 포함) 목표 금액이 즉시 다시 계산됩니다.
- **종목 관리** — **종목명으로 검색해서 추가**(삼성전자 → `005930.KS`). 구분/DCA/목표
  비중/밴드/리뷰 마감일 설정. 표시 이름은 따로 받지 않습니다 — 검색으로 확정된 종목명을 씁니다. 시세를 받지 못하면 "등록은 됐지만 시세 실패"를 사유와 함께
  경고로 알려줍니다.

금액·비중을 직접 치는 칸은 **천 단위 콤마**가 붙고(1,000,000), 브라우저가 붙이는 위아래 화살표는
쓰지 않습니다. 붙여넣은 "1,234,567원"에서도 숫자만 걸러냅니다.

종목을 치우는 방법은 두 가지입니다. **목록에서 감추기**(비활성화)는 받아둔 시세·지표·매수 기록을
그대로 두고 화면에서만 뺍니다. **완전 삭제**는 그 기록까지 전부 지우며 되돌릴 수 없어, 한 번 더
확인을 받습니다.

헤더의 **전체 새로고침** 버튼으로 활성 종목 전체 시세를 한 번에 갱신할 수 있고, 오른쪽 아이콘으로
다크/라이트 테마를 전환합니다(브라우저에 저장됨).

## 국내주식과 통화

국내주식은 야후 표기(`005930.KS` 코스피 / `247540.KQ` 코스닥)를 쓰지만, **종목 관리 화면에서
종목명이나 6자리 코드로 검색**하면 됩니다.

```
삼성전자   → 005930.KS (코스피)
에코프로비엠 → 247540.KQ (코스닥)
KODEX 200 → 069500.KS (코스피, ETF)
005930    → 005930.KS
```

검색은 이 순서로 찾습니다. 앞에서 찾으면 뒤는 보지 않으므로, 평소 검색은 네트워크 없이 끝납니다.

1. 이미 티커 형태인지 (`VOO`, `005930.KS`)
2. 내장 목록 (`backend/app/data/krx_seed.json` — 주요 종목·ETF, **네트워크가 막혀도 동작**)
3. DB에 캐시된 한국거래소 상장목록
4. 한국거래소 상장목록 온라인 조회 (받으면 캐시)
5. 야후 검색 API

내장 목록은 주요 종목 위주(약 176종목)라 중소형주는 들어 있지 않습니다. 그래서 앱을 켜면
잠시 뒤 백그라운드로 한국거래소 상장목록 전체를 한 번 받아 캐시하고, 이후에는 주 1회
갱신합니다. 못 받아도 내장 목록으로 검색은 계속 됩니다. 종목 관리 화면의 안내 문구가
**지금 무엇으로 검색되고 있는지**(내장 목록인지, 거래소 목록 몇 종목을 언제 받았는지) 그대로
보여줍니다.

> 서버가 임의로 종목을 고르지 않고 **후보를 보여주고 사용자가 확인**하게 돼 있습니다.
> 종목코드를 잘못 짚으면 다른 회사의 시세를 받아오는데, 그건 "못 찾았다"보다 나쁘기 때문입니다.
> 모르는 6자리 코드는 코스피/코스닥을 구분할 수 없으므로 양쪽을 모두 후보로 제시합니다.

### 통화

종목의 거래 통화(원화/달러)는 티커에서 자동으로 정해지며, 화면 곳곳에서 구분됩니다.

- **가격·주문 금액**은 그 종목을 실제로 거래하는 통화로 표시합니다 (원화는 정수, 달러는 센트까지).
- **비중 계산은 반드시 기준통화로 환산한 뒤** 합산합니다. 환산 없이 더하면 달러 1주가 원화 1주와
  같은 무게로 잡혀 비중이 완전히 틀어집니다.
- 리밸런싱 화면에서 **기준통화(원/달러)를 고르고 적용 환율을 확인·수정**할 수 있습니다.
  환율은 자동 조회하되 직접 입력한 값이 항상 우선하며, 조회에 실패해 추정치를 쓰는 중이면
  화면에 그렇게 표시됩니다.

거래일 캘린더도 시장별로 나뉩니다 — 국내 종목의 기간 경계와 리뷰 마감일은 한국거래소(XKRX)
휴장일을, 해외 종목은 NYSE 휴장일을 따릅니다.

## 로컬 실행

### Windows — 더블클릭으로 실행

1. **`setup.bat`** — 처음 한 번만 더블클릭 (venv 생성, 백엔드/프런트엔드 패키지 설치)
2. **`start-all.bat`** — 그 다음부터는 이것만 더블클릭하면 백엔드/프런트엔드가 각자 창에서 켜지고, 잠시 후 브라우저가 자동으로 열립니다

개별 실행이 필요하면 `start-backend.bat` / `start-frontend.bat`을 따로 실행해도 됩니다.

- **`update.bat`** — 최신 코드 받기 + 패키지 갱신을 한 번에 (더블클릭)
- **`diagnose.bat`** — 시세를 못 받을 때 **어디서 막히는지** 진단 (`diagnose.bat TSM`처럼 티커 지정 가능. 국내 티커를 주면 종목명 검색·환율까지 같이 검사합니다)
- **`verify.bat`** — 시세가 들어온 뒤 **받은 값을 믿어도 되는지** 검증 (액면분할 반영, 제공자 간 종가 일치, ETF·우선주·코스닥)

> 화면 왼쪽 위에 실행 중인 버전(`v0.4.0 (커밋)`)이 표시됩니다. 업데이트 후에도 값이 그대로면
> 서버를 다시 켜지 않은 것이니, 열려 있는 창을 모두 닫고 `start-all.bat`을 다시 실행하세요.

### 백엔드 (수동 실행 / macOS·Linux)

```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

최초 실행 시 `signal_dashboard.db` (SQLite)가 자동 생성됩니다. 매일 새벽(UTC 22:30, 미국 장 마감
이후) 활성 종목 전체를 자동 갱신하는 스케줄러가 함께 시작됩니다. 스케줄러 없이 띄우려면
`SIGNAL_DASHBOARD_DISABLE_SCHEDULER=1` 환경변수를 설정하세요.

### 프런트엔드

```bash
cd frontend
npm install
npm run dev
```

`http://localhost:5173`에서 접속하며, `/api/*` 요청은 `vite.config.ts`의 프록시 설정을 통해
백엔드(`http://localhost:8000`)로 전달됩니다.

## 종목 추가 흐름

종목 관리 화면에서 티커를 입력해 추가하면, 백엔드가 전체 히스토리를 백필하고 지표/시그널을
계산합니다. 네트워크가 막혀있거나 실패해도 종목 등록 자체는 유지되며, 이후 "시세 갱신"
버튼으로 재시도할 수 있습니다.

## 시세 수집

한 곳이 막히면 앱 전체가 멈추므로 제공자를 여러 개 두고 순서대로 시도합니다.

| 제공자 | 다루는 시장 | 방식 | 비고 |
| --- | --- | --- | --- |
| `yahoo` | 국내·해외 | yfinance | 봇 차단(쿠키/크럼) 때문에 환경에 따라 막힐 수 있습니다 |
| `stooq` | 해외 | CSV 한 방 | API 키 불필요. 한국거래소는 다루지 않습니다 |
| `naver` | 국내 | 일봉 JSON | API 키 불필요. 야후가 막힌 환경의 국내주식 경로 |

기본 시도 순서는 시장별로 다릅니다.

- 해외: `yahoo` → `stooq`
- 국내: `naver` → `yahoo`

국내주식에 네이버를 먼저 두는 이유는, Stooq가 한국거래소를 다루지 않아 야후가 막히면 국내
종목에는 대체 경로가 아예 없어지기 때문입니다. 다룰 수 없는 티커는 아예 시도하지 않습니다 —
Stooq에 국내 종목을 물어보면 "그런 심볼 없음"이 돌아오는데, 그게 실패 사유로 뜨면 종목코드
오타로 오해하게 됩니다.

모든 제공자의 종가는 분할(split)만 반영하고 배당 재투자 조정은 하지 않은 값이라, 스펙의
investing.com 종가 기준 백테스트와 정합성이 맞습니다.

저장할 때 **어느 제공자가 준 값인지**(`price_daily.source`) 함께 기록하고, 대시보드 카드에
"기준일 2026-09-15 · 네이버 시세"로 보여줍니다. 갱신할 때는 **지금까지 그 종목을 받아온
제공자를 먼저** 시도합니다 — 제공자마다 종가 기준이 조금씩 다를 수 있어서, 한 종목의
히스토리는 되도록 한 곳에서만 받아야 이어붙인 지점에서 지표가 튀지 않습니다. 그쪽이 막혀
있으면 평소 순서대로 넘어가고(값이 없는 것보다는 낫습니다), 출처가 바뀌면 경고 로그가
남습니다. 실제로 두 제공자의 기준이 같은지는 `verify_live.py`가 확인합니다.

### 갱신 속도

전체 새로고침은 종목별로 "조회 → 저장"을 반복하지 않고, **시세를 한꺼번에(동시에) 받아온 뒤
저장만 차례로** 합니다. 조회 시간은 거의 전부 응답을 기다리는 시간이라, 20종목이면 왕복이
20번 쌓이던 것이 동시 4건으로 줄어듭니다 (`MAX_FETCH_WORKERS`). DB 세션은 스레드 간에 나눠
쓸 수 없으므로 저장은 지금처럼 한 줄로 이어서 하고, 한 종목의 실패는 그 종목에만 남습니다.

지표는 갱신할 때마다 과거 전 구간을 다시 계산하지만(중간 값이 조용히 틀어지는 걸 막기
위해서입니다), 저장은 **바뀐 행만** 합니다. 10년치 한 종목 기준 갱신 후처리가 530ms →
105ms로 줄었고, 결과 값은 전과 동일합니다.

환경변수로 조정할 수 있습니다:

- `SIGNAL_DASHBOARD_PROVIDERS` — 공통 시도 순서 (예: `stooq,yahoo`)
- `SIGNAL_DASHBOARD_PROVIDERS_KR` / `SIGNAL_DASHBOARD_PROVIDERS_US` — 시장별 순서 (공통 설정보다 우선)
- `SIGNAL_DASHBOARD_HTTP_TIMEOUT` — 요청 타임아웃 초 (기본 30)

### 시세를 못 받을 때

**`python diagnose.py VOO`** (backend 폴더, 가상환경 활성화 상태)를 실행하면 DNS → 일반
HTTPS → curl_cffi → yfinance → 앱 수집 경로 순으로 나눠 검사해 어느 단계에서 막히는지
알려줍니다. 백신·방화벽의 TLS 간섭인지, 야후의 차단인지, 티커 오타인지 구분됩니다.
국내 티커(`python diagnose.py 005930.KS`)를 주면 시장에 맞는 제공자 순서로 검사하고,
종목명 검색(한국거래소 상장목록)과 환율까지 이어서 확인합니다.

### 받은 값이 맞는지 확인할 때

연결이 되는 것과 값이 맞는 것은 다릅니다. **`python verify_live.py`**는 자동 테스트로
덮을 수 없는 것 — 바깥 서비스가 실제로 무엇을 돌려주는지 — 만 검사합니다:

| 검사 | 틀리면 생기는 일 |
|---|---|
| 네이버 응답의 컬럼 이름 | 컬럼명이 바뀌면 수집이 통째로 멈춤 |
| 액면분할 소급 반영 여부 | 분할일에 가짜 급락이 생겨 그 구간 지표가 전부 틀어짐 |
| 네이버·야후 종가 일치 | 한 시계열에 다른 기준이 섞여 이어붙인 지점에서 지표가 튐 |
| ETF·우선주·코스닥·해외 | 보통주만 되고 나머지가 조용히 실패 |
| 환율 | 통화가 섞인 포트폴리오의 비중이 추정치로 계산됨 |

> 참고: `yf.download()`는 실패해도 예외를 내지 않고 빈 결과를 돌려줘서 원인을 알 수 없습니다.
> 그래서 앱과 진단 스크립트 모두 `Ticker.history(raise_errors=True)`를 씁니다.

## 테스트

```bash
# 백엔드
cd backend && source .venv/bin/activate && pytest

# 프런트엔드
cd frontend && npm test
```

커버리지를 함께 보려면 `pytest --cov=app` / `npm run test:coverage`.
두 테스트 모두 실제 네트워크를 쓰지 않습니다 — 백엔드는 conftest가 바깥 요청을 막고,
프런트엔드는 API 호출을 가짜로 대체합니다. 네트워크 상태에 따라 결과가 흔들리지
않아야 하고, 시세 서버가 막힌 환경에서도 그대로 돌아가야 하기 때문입니다.

지표(MA/StdDev/ROC/이격도/Wilder DMI-ADX), 시그널 조건식, 매수 워크플로우, 리밸런싱/비중조절
신호, API 라우터까지 단위·통합 테스트로 커버되어 있습니다. yfinance 실제 호출은 네트워크가
필요하므로 테스트에서는 mock 처리됩니다.

`tests/test_knee_conditions.py`는 대시보드가 내려주는 매수 조건 분해가 실제 시그널
엔진(`compute_signals`)과 모든 거래일에서 같은 결론을 내는지 대조합니다 — 두 경로가 갈라지면
화면과 시그널이 어긋나므로 반드시 함께 유지되어야 합니다.

`tests/test_providers.py`와 `tests/test_providers_korea.py`는 응답 파싱·실패 원인 분류·시장별
제공자 라우팅·폴백 동작을 검증하고, `tests/test_data_ingestion.py`는 "야후가 막힌 환경에서
대체 제공자로 받아 지표까지 산출되는지"를 전 구간으로 확인합니다. 실제 네트워크는 쓰지 않습니다.

`tests/test_symbols.py`는 종목명 해석을, `tests/test_fx.py`는 환율 적용 순서를,
`tests/test_rebalance.py`는 통화가 섞였을 때 비중이 기준통화로 환산돼 계산되는지를 확인합니다.
`tests/test_markets.py`는 내장 종목 목록의 형식(6자리 코드·중복 없음)까지 검사하고,
`tests/test_migration.py`는 **기존 DB 파일이 데이터 손실 없이 새 스키마로 올라오는지**를
옛 스키마를 직접 만들어 확인합니다.

프런트엔드(`npm test`)는 계산과 표기를 나눠 검증합니다.

- `src/lib/orderPlan.test.ts` — 주문 계획의 통화 환산. 비중·목표 금액은 기준통화로,
  주문 금액과 주수는 현지 통화로 나오는지 (여기가 틀리면 주문 주수가 환율만큼 어긋납니다)
- `src/lib/display.test.ts` — 통화별 표기(원화 정수 / 달러 센트), 지표 해석, 신호등 판정
- `src/pages/*.test.tsx` — 화면에 실제로 원화·달러가 맞게 찍히는지, 합계가 통화를
  섞어 더하지 않는지
- `src/components/SymbolSearch.test.tsx` — 종목명 검색·후보 선택·키보드 조작
- `src/api/client.test.ts` — 백엔드 오류의 안내(hint)와 기술적 원인(detail) 분리

## 알려진 제약

- 종가는 분할(split)은 반영하되 배당 재투자 조정은 하지 않은 값을 사용합니다 (`SIGNAL_APP_SPEC.md`의
  investing.com 종가 기준 백테스트와 정합성을 맞추기 위함).
- 지원 시장은 한국(코스피/코스닥)과 미국입니다. 다른 거래소를 추가하려면 `app/markets.py`의
  시장 판별과 `app/services/trading_calendar.py`의 캘린더만 늘리면 됩니다.
- 한국거래소 상장목록에는 ETF/ETN이 포함되지 않아, ETF는 내장 목록과 야후 검색으로 찾습니다.
- 시세 출처(`price_daily.source`)는 이 기능이 생긴 뒤 받은 시세부터 기록됩니다. 그 전에 받아둔
  행은 출처가 비어 있습니다 — 다시 내려받게 만들지 않으려고 그대로 뒀습니다.
- **해외주식은 티커로 입력합니다.** 공백 없는 영문 한 단어는 티커로 먼저 해석하므로
  (`VOO`를 네트워크 없이 바로 처리하기 위함), "apple"은 `APPLE`이라는 티커로 잡힙니다.
  회사명으로 찾으려면 "apple inc"처럼 띄어 쓰면 야후 검색까지 진행됩니다.
- 매수 추천은 자동으로 "확정"되지 않습니다 — 대시보드에서 "매수완료 확인"을 눌러야 확정되고,
  이때 보유수량에 반영할지 선택할 수 있습니다.
- 매도(리밸런싱) 실행일은 항상 고정 리뷰 마감일이며, 비중조절 신호(밴드 초과/미달, 정기 리뷰 도래)는
  조기 참고 알림일 뿐 자동 매매를 트리거하지 않습니다.
