## 3. safearea.mjs 측정 논리
- **찬성**: 흉내 방식이 맞다. CSS 응답의 `env()` 를 바꿔 끼우고 서비스 워커를 막는다(safearea.mjs:148·161-167). index.css 의 `env()` 대체값은 모두 `0px` 이라 정규식이 다 잡는다. 흉내가 아예 안 되면 제목이 위쪽 47 안으로 들어가 실패로 크게 드러난다.
- **걱정 (고쳐야 함)**: 제목 고르는 식이 주석의 뜻과 다르게 동작한다. `querySelector('.modal-title h3, .modal-title, h3')`(safearea.mjs:98)는 앞에 적힌 것을 먼저 고르지 않고, 문서 순서에서 먼저 나오는 것을 고른다. 그래서 늘 h3 대신 부모인 `.modal-title` 상자를 잡는다. 이 상자는 지금 줄바꿈을 허용해(`flex-wrap: wrap`) 안내 글이 둘째 줄로 내려가면 키가 커진다. 그러면 `close-first-row` 의 겹침 판정(105행)이 느슨해진다. 제목 둘째 줄 높이에 있는 ✕ 도 통과한다.
- **제안**: `modal.querySelector('.modal-title h3') ?? modal.querySelector('.modal-title')` 처럼 순서대로 찾는다.
- **걱정 (고쳐야 함)**: `sticky-head` 가 아무것도 확인하지 않고 통과할 수 있다. 팝업이 실제로 스크롤되는지 확인하지 않는다(110-115행). 첫 검토(0-review 5)는 "종목별 알림"을 펼친 뒤에야 400px 을 내릴 수 있었다.
- **제안**: `scrollHeight - clientHeight ≥ 200` 이 아니면 "검사 안 됨"으로 적는다. 또는 먼저 펼친다.
- **걱정 (참고)**: `foot-aligned` 는 저장 줄 아래 끝만 본다(125행). 정작 사용자에게 문제가 되는 "저장 단추가 홈 표시줄 위에 있나"는 재지 않는다. 단추 아래 끝 ≤ `innerHeight - inset.bottom` 을 더한다. CSS 바꿔 끼우기가 0번 일어났으면 실패로 끝내는 줄도 하나 넣으면 좋다.
