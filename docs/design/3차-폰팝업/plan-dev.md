대상: `origin/claude/design-3-phone-popups` (82f0582), 기준 b3a2d5e. 코드에서 바뀐 것은 `frontend/src/index.css` 하나(+43 −2)다. `.tsx`, `backend/`, `api`, `lib` 는 diff 가 없다. 화면을 띄워 재지는 않았고, 코드를 읽어서 판단했다.

## 1. CSS·문구만으로 되나 (2-2)
- **찬성**: 2-2 "해도 되는 것"(CSS) 안에서 끝난다. 새 상태, 컴포넌트 나누기, 이동 경로 변경은 없다. `aria-label` 과 role 도 그대로다. "먼저 물어야 하는 것"에 해당하는 항목은 없다.
- **걱정 (참고)**: 계획서와 커밋 해시가 맞지 않는다. 계획서는 머리줄 고침을 `20db93f` 라고 적었는데, 이 커밋은 `origin/claude/mobile-modal-safe-area` 에만 있다. 이 브랜치에서는 `1518486` 이다(plan-draft.md 머리말·문제 표 #2).
- **제안**: 계획서 해시를 `1518486` 으로 바로잡는다.

## 2. 건드린 파일과 범위
- **찬성**: 범위를 문제 표 1~5 에 맞췄다. 검사 도구(`audit.mjs`, `safearea.mjs`)는 `docs/` 아래에 따로 있다. 합격 기준 3 "`.tsx` 변경 없음"은 지금 그대로 지켜져 있다.
- **걱정 (참고)**: ≤640 팝업 규칙이 두 곳으로 흩어졌다. 대부분은 index.css:2929-2990 에 있고, `.stock-edit-foot` 만 index.css:4864-4872 의 별도 `@media` 에 있다. 기본 규칙(4853)보다 뒤에 있어야 이기는 순서 의존인데, 주석으로만 지켜진다.
- **제안**: 그대로 두되 주석은 유지한다. 아니면 `.stock-edit-modal .stock-edit-foot`(0,2,0)로 특이도를 올려, 위치를 옮겨도 깨지지 않게 한다.

## 3. 전역 규칙이 다른 화면에 퍼지는 곳
- **찬성 — `.modal-backdrop` 의 `max()` padding (index.css:2145-2146)**: PC 에서는 env()=0 이라 20px 그대로다. ≤640 에서는 `padding:0` (index.css:2272)이 덮어서, 실제로 바뀌는 건 >640 가로 폰뿐이다. 거기서는 옆 47, 위 20, 아래 21 이 된다.
- **찬성 — `.modal { max-height:100% }` (index.css:2154)**: 바깥 상자가 `position:fixed; inset:0` 이라 높이가 정해져 있고, %는 padding 을 뺀 안쪽 높이로 풀린다. PC 에서는 예전 `calc(100vh - 40px)` 과 같은 값이다. iPad 나 가로 Safari 에서는 주소창을 포함하던 100vh 보다 오히려 정확하다. ≤640 에서는 100vh(2277)와 100dvh(2931)가 다시 덮는다. 짧은 팝업은 상한이라 영향이 없다. `.modal` 은 모든 컴포넌트에서 `.modal-backdrop` 의 바로 아래 자식이다(12개 `.tsx` 확인).
- **걱정 (참고) — 가운데 카드 padding 되돌림 (index.css:2947-2951)**: `.confirm-modal` 과 `.modal` 은 특이도가 같고, 뒤에 와서 이긴다. 그런데 이 카드의 높이 상한은 ≤640 의 `max-height:100dvh`(2931)에 `margin:16px`(2287)을 더한 것이다. 확인 문구가 길면 카드가 화면보다 32px 커지고, 지금은 위 안전영역 padding 이 빠졌으니 위 끝이 상태바 밑에 깔릴 수 있다. 원래 있던 문제지만, 이번에 여백을 뺀 것과 맞물린다.
- **제안**: 두 카드에 `max-height: calc(100dvh - 32px - env(safe-area-inset-top,0px) - env(safe-area-inset-bottom,0px))` 를 준다. 선택자는 `.modal.confirm-modal` 로 올려 순서 의존을 없앤다.
- **걱정 (참고) — ≤640 `.modal-title { flex:1 1 0; flex-wrap:wrap }` (index.css:2957-2961)**: 모든 팝업 제목에 걸린다. 사용자, 차트, AI 분석, 매크로 팝업의 보조 문구(`.hint`)가 좁으면 h3 아래 줄로 내려간다. 예전에는 줄바꿈 없이 옆에서 줄어들었다. 의도에 맞고 잘리는 글도 없지만, 계획서가 말하지 않은 화면 변화다.
- **제안**: 계획서 6장에 "제목 보조 문구 줄바꿈"을 한 줄 적고, 사용자 팝업(UsersModal.tsx:116-125, 문구가 김) 360 스크린샷을 남긴다.
- **걱정 (참고) — `.modal-head > :not(.modal-title, .icon-btn)` (index.css:2967-2970)**: 특이도는 (0,2,0)이고 `.chip-row`(961)를 이긴다. ChartModal 은 칩 줄이 둘이라(ChartModal.tsx:227-253) 각각 한 줄씩, 모두 세 줄이 된다. 칩 수(탭 2~3개, 기간 4개)로 보면 예전에도 두 칩 줄이 한 줄에 들어가지 않았으니 줄 수가 늘지는 않는다. 다만 앞으로 머리줄 바로 아래에 다른 요소(안내 문구, 보조 버튼)를 넣으면 말없이 100% 폭 아랫줄로 밀린다. `push-modal` 처럼 `nowrap` 인 머리줄(2984)에 그런 요소가 생기면 찌그러진다.
- **제안**: 주석에 "머리줄 직속 자식은 제목·✕·칩 줄만"을 적는다. 아니면 선택자를 `.modal-head > .chip-row` 로 좁힌다. 지금 모든 사례가 칩 줄이므로 결과는 같고, 퍼지는 범위만 줄어든다.
- **찬성**: ConfirmDialog(✕ 없음)와 PushModal(제목+✕, nowrap)은 새 규칙과 충돌하지 않는다. 기존 `.modal-head .icon-btn { margin-left:auto }`(2187)이 남아 있어 ✕ 는 오른쪽 끝을 유지한다.

## 4. 브라우저 호환
- **찬성**: `env()`(iOS 11.2 이상), `max()`(Safari 11.1 이상, Chrome 79 이상), `:not()` 여러 인자(Safari 9 이상, Chrome 88 이상, Firefox 84 이상), flex 안의 % max-height 는 대상 PWA 환경(iOS Safari, 최신 Chrome)에서 모두 된다.
- **걱정 (참고)**: index.css:2145 에는 대체값이 없다. `max()` 를 모르는 브라우저에서는 선언 전체가 버려져 바깥 padding 이 0 이 되고, 카드가 화면 끝에 붙는다. `:not(a, b)` 를 모르는 브라우저(Chrome 88 미만)에서는 2967 규칙만 버려져 예전 배치로 돌아간다. 큰 문제는 없다.
- **제안**: 2145 앞에 `padding: 20px;` 한 줄을 대체값으로 둔다. `:not()` 은 `:not(.modal-title):not(.icon-btn)` 로 이어 써도 된다. 특이도가 (0,3,0)으로 오르지만, 다른 규칙과 충돌하지는 않는다.
