### 조건 (셋 — 고친 뒤 다시 잰다)

1. **[고쳐야 함] 저장이 실패하거나 "지우기"를 누르면 포커스가 `body` 로 떨어진다. 실패 뒤 Esc 를 누르면 창째 닫혀 친 값과 까닭이 사라진다.**
   - 측정(PC 1280, 키보드만): 달 칸 2035-01 · 예상 2.5 → Tab → "저장"에서 Enter.
     - `after keyboard 저장 fail, focus: OUT 자산관리…`(= BODY), 까닭 1개.
     - 이어서 Esc → `dialogs 0 focus NODIALOG 근원 PCE … — 차트`.
     - 폼만 닫혀야 하는데 **창이 닫혔다.** 마우스로 "저장"을 눌러도 같다(`fail→Esc(form) … form 0`, 다음 Esc 에 남은 창 없음).
   - 대조: 숫자 칸에서 Enter 로 저장하면 실패 뒤 포커스가 칸에 남는다(`Enter-in-input fail, focus: IN 근원 PCE 예상치`). 그때 Esc 는 폼만 닫는다(`dialogs 1 form 0 focus IN 예상치 입력`).
   - 까닭: `ForecastBox.tsx:137` "저장"은 `disabled={!canSave || busy}` 다. 저장 중에 단추가 꺼지면서 포커스를 잃는다. 그래서 `onFormKey`(form 의 onKeyDown)가 Esc 를 받지 못하고, 문서에 건 창 닫기가 받는다.
   - 지우기도 같다.
     - `2026-10 예상 지우기`에서 Enter → `after 지우기 focus: OUT 자산관리…`(BODY).
     - 그 줄이 사라지고, 단추도 `disabled={busy}`(:84)다.
     - 다음 Tab 은 가두기 덕에 창 첫 칸("1년")으로 돌아온다. 하지만 어디에 있었는지는 잃는다.
   - 첫 검토 조건 3("예상치 입력" 뒤 포커스가 body)과 같은 결이다. 새로 생긴 두 단추에서 다시 생겼다.
   - 고칠 방향(하나 고르면 된다)
     - 실패하면 숫자 칸(또는 저장 단추)으로 포커스를 돌려준다.
     - 아니면 busy 동안 `disabled` 대신 `aria-disabled` 로 두어 포커스를 지킨다.
     - 지운 뒤에는 남은 "지우기"나 "예상치 입력"으로 보낸다.
2. **[고쳐야 함] "예상과 같음"이 정확히 0일 때만 나온다. 화면에 같은 값을 넣으면 "예상보다 0.00%p 낮음"이 나온다.**
   - 재현: 관리자로 CPI 2026-10 예상을 화면 값 그대로 2.65 넣는다. 실제 값은 `2.6498840675720503`(`/api/macro`)이다.
     - 창: `2026-10 예상 2.65%예상보다 0.00%p 낮음 (관리자가 넣음)지우기`
     - 줄(320 라이트, 스크린샷 `shots/star-320x568-light-CPI.png`): "예상 2.65%, 예상보다 0.00%p 낮음". 바로 옆 값은 "2.65%"다.
   - 같은 숫자를 두고 "낮음"이라 말한다. 문구변경 표(사용자 확인 보완 첫 줄 "(낮음 · "예상과 같음")")가 약속한 "예상과 같음"이 실제로는 거의 나오지 않는다.
   - 까닭: `components/macro/period.ts:28` `if (surprise === 0)`. 서버 차이는 실수라 0이 되기 어렵다.
   - 고칠 것
     - 화면에 찍는 자릿수로 반올림한 뒤에 0이면 "예상과 같음"으로 한다(`macroChange` 가 0.00 을 내는 경우).
     - "예상과 같음" 테스트를 넣는다. 지금 테스트 이름("예상보다 낮으면 "낮음", 같으면 "예상과 같음"")은 낮음만 본다. 돌연변이 N4("예상과 같음" 글 바꾸기)가 **73개 다 통과**로 살아남았다.
3. **[고쳐야 함 — 테스트] "지우기는 관리자만"을 지키는 테스트가 없다.**
   - 돌연변이 N7: `removeButton` 의 `editable &&` 를 지우면 지인 · 손님 창에도 예상마다 "지우기"가 생긴다. 그런데 **73개 다 통과한다.**
   - 지인 테스트(`예상치가 없으면 지인에게…`)는 예상이 없는 데이터라 지우기가 처음부터 없다. 손님 테스트도 예상이 없다.
   - 고칠 것: 예상(발표 뒤 + 발표 전)이 있는 지인 · 손님 창에서 `예상 지우기` 단추가 0인지 본다.
   - 실제 화면은 지금 맞다. 지인 · 손님 창 `지우기 0`. 출처 "(관리자가 넣음)"은 보인다.
