## 하지 말아야 할 것 / 줄일 것

- **배포 전 "정교화" 라운드를 더 열지 않는다.** 0.45.1~0.45.3은 모두 "서버를 못 올리는 사이" 라운드였고, 남은 후보(0-1의 정교화 약 60조각: 이음표, "벌", "(12번)", ›가 다음 줄로…)는 실사용 뒤에 다시 고르면 절반은 사라진다.
- **차트 포인터 정밀화를 멈춘다.** 0.45.2 끝 검토 4회(불합격 1)가 흉내 마우스와 뮤테이션 생존 줄을 두고 돌았다. 실기기 확인 전에는 더 가지 않는다.
- **"뮤테이션 생존 0 = 합격선"을 화면 상호작용 코드에는 완화한다.** 0.44 B 검토 5회, 0.45.2 끝 검토 4회처럼 같은 동작(T3·T7 "같은 동작")에도 라운드가 늘어난다. 라운드 하나에 리뷰 파일이 15~28개다.
- **기능 추가를 멈추고 덜어낼 후보를 본다**(#9 데이터가 생긴 뒤). 후보: 표·카드 두 보기, 손익 통화 넷, 정렬 다섯, 시그널 카드의 지표 6칸 상시 노출.
- **개인화를 더 늘리지 않는다**(0-1 사용자화: "내 기준" 표시 확장 등). 규제 확인(#3) 전에는 3절이 가리킨 위험 쪽이다.
- **시그널 "근거 복원 보고서"의 그 뒤 움직임**(발동 뒤 수익 분포)은 주인 전용 문서로만 둔다. 화면에 올리면 3절 "이 시그널로 연 N%"가 된다.

## 문서 체계

- ROADMAP 2,756줄은 **기록으로는 훌륭하지만 기획 도구로는 무겁다.** 0-1 "다음 라운드 후보"가 긴 문단 안에 가운뎃점(·)으로 100개 넘게 이어지고, 우선순위, 언제 처음 나왔는지, 몇 번 밀렸는지가 없다. 0-1 표 제목은 아직 *(v0.37.0 뒤)*다(0.42 끝 검토 R2가 지적했고 그대로다).
  → 0-1을 표 하나로: `후보 | 처음 나온 판 | 밀린 수 | 규제·데이터 영향 | 크기`. 주인 확인은 따로 "배포 체크리스트" 한 장.
- README "화면 구성"(244줄)은 버전별 변경 기록이 되었다(v0.42 작은 고치기…v0.45.3). 지인이 읽을 "화면마다 무엇이 있나"는 짧게 두고, 변경 기록은 CHANGELOG로 뺀다.
- 0.45.3 status.md는 "상태: 끝"인데 맨 아래 "다음 할 일: 검토자 둘·사용자 판정을 기다린다"가 남아 있다. CLAUDE.md 진입 규칙("다음 할 일"부터 잇기)과 부딪친다.

## 잘 된 것

- **규제 선을 실질로 지켰다.** "추천"이라는 말을 걷었고(0.7), 매도 칩은 회색, 비중 배지는 상태로 말하며(glossary), AI는 설명만 하고 사용자 본인 키를 쓴다. 모든 라운드 계획에 "규제 영향" 칸이 있다.
- **데이터 경계(1절)와 "다시 만들 수 없는 것"을 가르는 원칙.** 평가금액 기록을 0.44에 시작한 판단이 맞았다. 공용 지표 + 읽을 때 판정하는 방식(내 기준)은 비용이 싸다.
- **첫 화면이 내 포트폴리오.** 확인할 신호, 총액, 다음 리뷰 D-68이 390px 한 화면에 들어온다(지인·주인 화면). 처음 온 사람 3단계 안내와 손님 매크로 둘러보기도 있다.
- **되돌릴 길과 호환**(응답 필드는 더하기만, 끄기 스위치, downgrade 도구, 응답 사진 차이 0)과 가짜 서버 + 데모 계정 넷은 운영 중인 개인 앱으로서 드문 수준이다.
- 용어집과 어포던스 표가 화면 말을 하나로 묶는다.
