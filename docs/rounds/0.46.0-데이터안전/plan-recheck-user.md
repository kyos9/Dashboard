# 0.46.0 계획 다시 보기 — 사용자 입장 (읽기만, 코드 안 봄)

`plan-user.md` 의 걱정을 기준으로 `plan.md` 에서 바뀐 부분만 봤다. 스크린샷은 앞서 찍은 `plan-user-shots/` 를 다시 봤다.

| 바뀐 부분 | 풀림 / 남음 |
| --- | --- |
| 화면 말 — 진단 백업 줄 | **풀림**: "매일 백업 N개(최대 7) · 업데이트 직전 N개(최대 3, 7일 안)"라서 "11개(최대 7개)" 같은 모순이 없어진다. 방침 문구를 그대로 두는 이유도 맞다. **남음(참고)**: 360폭에서 한 줄이 길어 두세 줄로 접힐 것이다(22-360l-diag.png 의 지금 줄도 이미 두 줄). |
| A2 실패 문구 | **풀림**: pg_dump 라는 말이 없어졌고, 데이터가 무사하다는 말이 들어갔다. **남음(참고)**: "DB"는 여전히 개발자 말이다("데이터"가 쉽다). 두 갈래 모두 주인이 **무엇을 하면 되는지**(가만히 두면 내일 다시 하는지)를 말하지 않는다. "백업 파일이 끝까지 써지지 않았습니다"에는 데이터가 무사하다는 말도 없다. |
| C 진단 줄 | **풀림**: 날짜 꼴을 진단에 맞췄고, 출처는 "시세 출처 Yahoo·Stooq"로 쓰며, 맨 위 요약이 이 줄을 따른다. **남음(고쳐야 함)**: 표에는 "실패가 많아 막힘" 문구만 있다. 막힘 (나)(실패 0 인데 2거래일 넘게 묵음) 때 뜰 말이 없다. 지금 꼴 그대로 나가면 "20종목 중 실패 0"과 "막힘"이 한 줄에 같이 서서 서로 다른 말을 한다. **남음(참고)**: 이 줄은 막혔다는 사실만 말한다. "그동안 알림은 10월 28일 값으로 판단된다"는, 주인이 원래 몰랐던 핵심은 말하지 않는다. |
| C ⋯ 점 풀이 | **풀림**: 가입 숫자와 따로 두고, 메뉴의 "진단" 줄에 이유(백업/시세)를 적는다 → 진단을 눌러야 한다는 걸 안다. **남음(참고)**: 숫자 "1"과 점이 함께 뜰 때 ⋯ 위에서 어떻게 보이는지(11-owner-menu.png 자리)가 계획에 없다. "진단을 확인하세요"가 폰(손가락, 마우스 올리기 없음)에서 어디에 보이는지도 계획에 없다. |
| D 확인 창 | **풀림**: 이름·이메일·종목 수가 보이고, 거절과 지우기가 어떻게 다른지, 되돌릴 수 없다는 것까지 적는다. **남음(참고)**: 이 설명은 "지우기"를 누른 **뒤에야** 보인다. 승인 대기한 사람을 없애려는 주인은 먼저 확인 없이 바로 되는 "거절"을 누르기 쉽다(24-360l-users.png). 다만 다시 승인할 수 있어 해는 작다. 위 풀이에 붙일 "지우려면 지우기"는 말이 덜 된 것처럼 읽힌다(거슬림). 360폭에서 세 문장짜리 확인 창은 길다. |
| A4 경고만 | **풀림**: 매주 받던 것이 OneDrive 때문에 조용히 멈추지 않는다. **남음(고쳐야 함)**: 작업 스케줄러가 bat 을 돌리면 창이 안 보여서 주인이 경고를 보지 못한다. 결국 "사본이 OneDrive(구름)로 올라간다"는 것을 끝내 모른다. 경고 문구도 "화면 말" 표에 없다. **남음(참고)**: 주인 확인 목록에 "받는 폴더가 OneDrive 아래인지"가 빠졌다(목록에는 스케줄러 계정만 있다). |
| 알림 설정 | 이견 1 에 달렸다. (가)를 고르면 설정 화면은 지금 그대로다(14-owner-push.png). |

**이견 1 — 사용자로서**: **(가)에 찬성**한다. 바뀐 날 한 번이라 드물고, 설정 화면 문구가 헷갈려지지 않는다(나는 360폭에서 세 줄로 접힌다). 다만 이 알림은 설정 화면에 없는 종류다. 그래서 푸시 글 자체에 "관리자에게만 가는 알림"이라는 것과 끄려면 개발자에게 말하라는 것이 보이지 않으면, 주인은 "이건 어디서 온 알림이지?" 하고 헤맨다(참고).
