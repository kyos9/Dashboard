## A. 시그널 규칙을 한 곳으로 (확정 내용)

1. `services/signal_rules.py` — 조건 하나 = **메타데이터**(키·붙는 지표 칸·화면 이름표·풀이·열 머리·AI 문구) + **평가 함수**. 기준값(ADX 20, 거래량비 1.1, 이격도 0, 비교 5거래일)은 여기 상수로 한 번만. 정의 판(`version`)·변경 이력도 여기.
2. 평가는 **한 벌**: 표 전체(벡터)로 계산하고, 오늘 한 줄(`knee_conditions`)은 최근 행을 같은 평가에 넣어 마지막 행을 쓴다. OR 묶음은 지금 규칙 그대로 — "참이 하나면 참, 둘 다 판정 불가면 판정 불가, 나머지는 거짓"(명세 3장). 저장 판정은 판정 불가를 거짓으로 접는다(지금과 같음).
3. 화면·AI 가 쓰는 문구 전부를 규칙에서: 열 머리, 조건 칩, 시그널 보기 설명 줄, 신호등 풀이("조건 4개"), `AiPanel` "네 조건", AI 지시문(`SIGNAL_RULES`, 시스템 지시문의 "네 조건 중 몇 개", ①~④ 줄), 지표 색 풀이의 기준값(ADX "추세 없음", 거래량비 "거래량 증가" — 조건과 같은 숫자를 쓰므로 함께).
4. API (**더하기만**): `GET /api/signal-rules` — 공용·**로그인한 사용자만**(`SHARED, USER`). 손님 문은 넓히지 않는다. 대시보드 카드에 `buy_conditions`(규칙의 키 그대로)와 `signal_rules_version`. 옛 `knee_conditions` 는 그대로 채운다.
5. 화면: `card.buy_conditions ?? card.knee_conditions`. 규칙은 한 번 받아 두고, 카드의 판이 다르면 다시 받는다(며칠 떠 있는 PWA). 규칙을 못 받으면(옛 서버 404) 지금 문구 그대로 — **기본값이 지금 문구와 같으므로 깜빡임이 없다.**
6. 명세: 3·4장은 뜻, 정의는 `signal_rules.py`. 10장 바꾸는 순서를 새 길로. **11장 정의 변경 이력** 신설.

## B. 정의를 바꿀 때의 길 (확정 내용 — 자동/명령은 주인 답에 따라)

1. **정의 지문** = 평가 부분(조건 키·기준값·손으로 올리는 `version`) + 지표 정의 판. 문구·이력은 넣지 않는다(글자 고칠 때마다 전 종목 재계산 X). 지표 판이 바뀌면 지표까지 다시 계산.
2. **재계산** — 저장된 시세로 전 종목. 네트워크 없음.
   - (자동이면) 스케줄러의 켠 직후 job **안에서 따라잡기 갱신보다 먼저, 차례로** 돈다 → 같은 종목을 동시에 쓰지 않는다. 스케줄러를 맡은 프로세스 하나만(리더 락).
   - 지문은 **전부 성공했을 때만** 저장. 실패한 종목은 로그·진단에 남고 다음 시작 때 다시.
   - 명령 `python -m app.tools.recompute_signals` 는 어느 쪽이든 둔다.
   - 걸리는 시간: 종목당 0.1초(SQLite, ROADMAP 1절)~0.25초(Postgres 10년치, 9-1). 300종목이면 30~75초.
3. **전후 비교 도구** `python -m app.tools.signal_diff` — 저장된 판정 vs 지금 코드의 정의: 종목별 1·3·5년 **매수·매도** 발동 횟수(전→후), 오늘 상태가 바뀐 종목, 마지막 매수 시그널 날짜가 바뀐 종목, 알림이 갈 사람·종목 수(실제 알림 판정 `alerts.current_values` 를 보내지 않고 돌려 저장된 상태와 비교). 수익률·그 뒤 움직임 없음.
4. `app_settings` 에 글자 값용 `get_value`/`set_value` 를 따로 둔다. 관리자 설정 응답에는 나오지 않는다.
5. 진단(주인만, 관리자 API): "시그널 기준 판 · 마지막 재계산 시각 · 바뀐 행 수 · 실패 종목".
6. 가짜 서버(스케줄러 꺼짐): 시작 때 같은 함수를 직접 부른다. 데모로 지문을 옛 것으로 만들면 재계산·진단 줄을 화면에서 확인.
7. `DEPLOY.md`: 정의를 바꾼 이미지는 배포 전에 백업 DB로 `signal_diff` 를 먼저 돌린다 · 0.40.x 로 내리면 자동 재계산이 없다(다음 갱신 때 따라옴).

**완료 조건**: 지문이 다르면 한 번만 돈다(두 번째 시작엔 안 돈다) · 일부 실패면 지문 저장 안 함 · 재계산이 실패해도 앱이 뜬다 · 따라잡기 갱신과 겹치지 않는다(순서 테스트) · 지난 날짜만 바뀌면 알림 0, 오늘이 켜지면 한 번(테스트) · 비교 도구가 미리 정한 변경(ADX 20→25)에서 고정한 숫자를 낸다(테스트) · 워커 둘이면 하나만(Postgres 갈래)

## 이견 — 주인에게

**"기준을 바꾼 날" 표시를 이번에 만들지**
- 개발: 이번엔 정의를 안 바꿔 보일 일이 없다 → 확인할 화면이 없으니 정의를 바꾸는 라운드에서.
- 사용자: 자동 재계산을 만들면 그날 숫자가 말없이 바뀐다 → 길과 표시를 같이 만들어야 한다.
- 총괄 추천: **이번에 자리만 만든다**(이력이 하나면 안 보임 → 지금 화면과 같음). 데모(가짜 서버)에서 이력을 둘로 만들어 확인할 수 있으므로 개발 쪽 걱정(확인할 화면 없음)이 풀린다.

3. 바꾼 날 표시 — 신호 요약 카드 안 한 줄 "시그널 계산 방식이 YYYY-MM-DD에 바뀌었습니다"(추천, 바꾼 뒤 30일) / 시그널 보기 맨 아래 설명 줄 / 표시 안 함
