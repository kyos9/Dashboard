# 0.45.4 초안 — 빈틈 막기

이 라운드는 제로베이스 점검에서 나왔다. 점검 종합은 `docs/audit/2026-10-23-제로베이스/종합.md`에 있고, 그중 1~6번과 14번을 다룬다.
- **크기**: 중간(항목 셋). 마이그레이션 0, 새 테이블·컬럼 0, 응답 필드는 더하기만 한다.
- **규제 영향**: A에 있다(AI 종목 분석 틀). 주인이 이미 정했다: "지인엔 중립 틀". 그래서 이 라운드는 규제 선을 넓히지 않고 좁힌다.
- **서버**: 0.44.0이고, 0.45.0~0.45.3과 함께 올라간다. 되돌릴 때는 이미지 태그만 바꾸면 된다. DB가 바뀌지 않기 때문이다.

## A. 방침을 실제와 맞추고, 지인의 AI 종목 분석은 중립 틀로 (중간, 규제 영향: 좁힘)

**왜**: 방침 3절은 AI에 "보유수량·평단가·목표비중처럼 나의 포트폴리오는 보내지 않"는다고 적었다. 그런데 **포트폴리오 진단**과 **종목 분석**은 비중(현재·목표·차이)과 수익률(%)을 보낸다(`ai_portfolio.py:1-9`). 두 기능 이름도 방침에 없다. 종목 분석의 지시문은 주인의 개인 전략으로 짜여 있다. "core-alpha-hedge, 알파버킷 편입 판단 적합/조건부/부적합, 사이징 코멘트(동일비중 5%)"인데, 이 지시문이 `AI_ADVICE_FOR_USERS` 기본 True로 지인에게도 그대로 나간다.

**무엇**:
1. **방침 3절 고치기.** 두 기능의 이름을 적는다. 두 기능은 **내 비중(%)과 수익률(%)**을 보내고, 금액·수량·평단가·현금 액수는 보내지 않는다. 종목 분석은 AI 회사가 웹 검색을 한다. 이때 검색어에 비중을 넣지 않게 지시한다. 관리자가 두 기능을 사용자에게 닫을 수 있다는 것도 적는다. 4절의 기기 저장 목록에는 빠진 것을 채운다. 대시보드 정렬·보기·손익 통화, 리밸런싱 "매수만 보기"다(`lib/portfolio.ts:148-150`, `RebalancePanel.tsx:977`). `POLICY_EFFECTIVE`도 바꾼다.
2. **방침 시험이 데이터 흐름을 대조하게 하기.** `test_policy_page.py`에 시험을 더한다. 포트폴리오 문맥을 만드는 함수가 실제로 내보내는 열쇠(비중·수익률)를 보고, 방침 글에 그 기능 이름과 "비중"·"수익률"이 있는지 본다. 반대로 금액 열쇠(`current_value` 등)가 문맥에 나타나면 실패한다. 이 시험은 이미 있는 "%만 보낸다" 시험과 겹치지 않게 방침 쪽만 맡는다.
3. **종목 분석 지시문을 둘로 나누기.**
   - **주인(관리자)**은 지금 글자 그대로 쓴다(바이트 같음, 시험으로 고정).
   - **다른 사용자**는 중립 틀을 쓴다. 1~5절(개요·지표·강점·리스크·시나리오)은 같다. 다만 3절 "알파 종목으로서 지수 대비 초과수익"은 "이 회사가 경쟁사보다 나은 점"으로 바꾼다.
   - 6절은 **"내 포트폴리오와 겹치는 점"**으로 바꾼다. 같은 업종·밸류체인 종목의 이름과 비중만 적는다. 판단(적합/부적합), 사이징, 편입 권유는 없다.
   - 첫 단락의 core-alpha-hedge·동일비중 5%도 뺀다.
   - 지시문 7번의 "버킷·익스포저 판단"은 "사용자가 붙인 분류가 있으면 겹치는 점을 볼 때 쓴다"로 바꾼다.
   - 어느 틀을 쓸지는 `research_job`이 그 사람의 `is_owner`로 고른다. 화면의 "보내는 내용 보기"에 지시문이 그대로 보이므로 따로 고칠 것이 없다.
   - 화면 제목이나 섹션 이름이 지시문 제목("6. 알파버킷 편입 판단")을 기대하는 곳이 있는지 본다(`AiPanel.tsx`, `ChartModal.test.tsx`).

**데이터·호출**: 바뀜 없다. 보내는 숫자도 같다. 바뀌는 것은 지시문 글뿐이다.
**화면 말**: 방침과 지인이 보는 AI 리포트의 6절 제목이 바뀐다. 용어집도 고친다.
**부딪히는 결정**: ROADMAP 9-8(사용자가 준 틀)과 9-15(사용자에게도 연다, 기본 연다)다. 이번에는 **주인에게만 9-8 틀**을 쓰고, 9-15의 열고 닫기는 그대로 둔다. ROADMAP 3절에 한 줄 더한다.
**되돌리기**: 이미지 태그.
**완료 조건**:
- 방침 시험이 새로 있다. 종목 분석·포트폴리오 진단 문맥에 금액 열쇠를 넣는 뮤테이션을 하면 시험이 잡는다. 방침 글에서 "종목 분석"을 지우는 뮤테이션도 잡는다.
- 주인 지시문이 바이트 단위로 그대로다.
- 사용자 지시문에 `편입|사이징|알파|적합|동일 비중|core-alpha`가 0개다(grep 시험).
- 사용자 지시문의 6절 제목이 "내 포트폴리오와 겹치는 점"이다.
- `/api/ai/research/{t}/context`의 응답에서 주인은 주인 틀을, 친구는 중립 틀을 받는다.

## B. 웹 보안 기본값 (중간)

**왜**: 응답에 보안 헤더가 하나도 없다. AI 키는 브라우저 localStorage에 있다. 그래서 XSS가 하나만 생겨도 키가 샌다. `/docs`·`/redoc`·`/openapi.json`이 로그인 없이 열린다. 입력 길이와 본문 크기에 한도가 없다. 나가기는 쿠키만 지운다. Starlette 0.41.3에는 알려진 권고가 있다.

**무엇**:
1. **보안 헤더 미들웨어**(앱 안, 그래서 PC와 서버에 같이 적용된다).
   - 모든 응답에 붙이는 것: `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: DENY`, `Permissions-Policy`(카메라·마이크·위치 끔).
   - HTTPS로 온 요청에만(`X-Forwarded-Proto` 또는 scheme이 https) 붙이는 것: `Strict-Transport-Security: max-age=15552000`. includeSubDomains는 붙이지 않는다. 주인 도메인의 다른 하위 도메인을 모르기 때문이다.
   - **CSP**: `default-src 'self'; script-src 'self' 'sha256-<index.html 안의 테마 스크립트>'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; connect-src 'self'; font-src 'self' data:; worker-src 'self'; manifest-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'`.
     - style-src에 unsafe-inline을 두는 것은 React의 `style=` 속성 때문이다.
     - 스크립트 해시는 서버가 켤 때 `dist/index.html`의 인라인 `<script>`에서 잰다. 그래서 빌드가 바뀌어도 맞는다.
     - 시험은 빌드한 `index.html`과 `frontend/index.html` 둘 다에 대해 해시가 맞는지 본다.
   - **끄는 스위치**: `.env`의 `SIGNAL_DASHBOARD_CSP=off`면 CSP만 뺀다. 다른 헤더는 남긴다. 실기기에서 화면이 깨질 때 이미지를 다시 받지 않고 끌 수 있게 하려는 것이다. 이 사용법은 DEPLOY.md에 적는다.
   - 가짜 서버의 로그인 흉내 페이지도 같은 헤더 아래에서 돌아야 한다.
2. **`/docs`·`/redoc`·`/openapi.json`을 닫는다.** `docs_url=None, redoc_url=None`으로 하고, openapi는 `/api/openapi.json`으로 옮겨 문지기 뒤에 둔다. 저장소 안에서 `/openapi.json`을 부르는 곳이 있는지 확인한다(devtools·스크립트·README).
3. **입력 한도**:
   - `StockCreate.ticker` ≤ 64자(종목명 검색어도 받으므로), `name` ≤ 100, `category` ≤ 40.
   - `StockUpdate`는 같게 한다. 순서 바꾸기 `tickers`는 ≤ 종목 수 한도(이미 있으면 그 값, 없으면 500).
   - 그 밖에 사용자 문자열을 받는 스키마를 훑어 길이가 없는 것을 같은 표로 채운다(표시 이름·메모·리밸런싱 기록 note 등). AI 요청 글처럼 한도가 이미 있는 것은 그대로 둔다.
   - 요청 본문은 **1 MB**를 넘으면 413이다(`Content-Length`로 보고, 없으면 읽으며 센다).
   - 옛 데이터에 한도보다 긴 값이 있으면 읽기는 그대로 되고, 고칠 때만 한도가 걸린다. 화면은 413·422를 지금 오류 문구 길로 보인다.
4. **"모든 기기에서 나가기"**: `POST /api/auth/logout-all`이 그 사람의 `session_epoch`를 1 올리고 쿠키를 지운다. 머리 ⋯ 메뉴 계정 칸의 "나가기" 아래에 둔다(확인 한 번). **지금의 "나가기"는 이 기기만**이다(바뀜 없음). 비밀번호 모드(구글 아님)에서는 나타나지 않는다. 사람별 epoch가 없기 때문이다. 격리 표에 줄을 더한다.
5. **의존성**:
   - `fastapi`를 Starlette 0.49.1 이상을 받는 판으로 올린다. 후보는 fastapi 0.120.x이고, Starlette 1.x로 넘어가는 판은 피한다.
   - `cryptography`를 지금 깔린 판으로 고정한다.
   - `pytest`·`httpx`는 실행용 requirements에서 `requirements-dev.txt`로 옮기는 것을 검토한다. **Dockerfile·CI·setup.bat이 무엇을 까는지 보고**, 바뀌는 곳이 셋 이상이면 이번에는 하지 않는다.
   - `.github/dependabot.yml`을 둔다(pip·npm·actions, 한 달에 한 번, PR만 만든다).

**데이터·호출**: 바뀜 없다. 새 엔드포인트가 하나 생긴다(logout-all, 자기 것).
**화면 말**: ⋯ 메뉴에 "모든 기기에서 나가기"와 그 확인 문구가 생긴다. 용어집에 더한다.
**부딪히는 결정**: 0.39 쪽지 v2(epoch는 관리자 차단 때만 오른다). 이번에 사람이 스스로 올리는 길을 더한다.
**되돌리기**: CSP는 스위치로, 나머지는 이미지 태그로.
**완료 조건**:
- 헤더 시험이 있다: 페이지·API·정적 파일·401·404에 붙는지, HSTS가 https일 때만인지, 스위치를 끄면 CSP만 빠지는지.
- Playwright로 1400·390·360 × 두 테마를 보고, 로그인 흉내·대시보드·팝업 차트·리밸런싱·AI 패널(가짜)·알림 창·서비스 워커 등록에서 **CSP 위반 콘솔 0**이다.
- `/docs`·`/openapi.json`은 404(또는 401)이고 `/api/openapi.json`은 로그인한 뒤 200이다.
- 한도 시험이 있다: 경계값, 413.
- logout-all 시험: 다른 기기의 쪽지가 401이 되는지, 이 기기의 쿠키도 지워지는지, 남의 epoch는 그대로인지. 격리 표가 맞는지.
- 전체 pytest가 새 의존성으로 통과하고, API 모양 비교에서 빠진 경로·필드가 0이다. openapi 경로 이동은 문서 경로라 API 모양에서 빼고 비교한다.

## C. 목표 비중을 비워 두면 생기는 "팔기"를 알린다 (작음)

**왜**: 지인이 막 넣은 종목에 "10주 팔기"가 떴다. 목표 비중을 비우면 0%로 저장되고, 주문 가이드가 0%에 맞추려고 전부 파는 계산을 하기 때문이다. 화면 어디에도 그런 말이 없다(점검 사용자 B1·N1).

**무엇**: **계산은 그대로 둔다**(기본값 그대로 규칙). 화면에서만 알린다.
1. 주문 가이드의 PC 표와 폰 카드에서, **보유 중이고 목표 0%인 줄**의 팔기에 짧은 꼬리를 붙인다: "목표 0% — 목표를 아직 정하지 않았다면 ✎ 수정에서 넣으세요".
   - 이런 줄이 둘 이상이면 표 위에 한 줄로 모은다: "목표 비중이 0%인 보유 종목 N개는 전부 팔기로 계산됩니다".
   - 목표 0%를 일부러 넣은(정리하려는) 사람에게도 거슬리지 않게 말을 고른다.
   - "매수만 보기"에서는 팔기가 없으므로 꼬리도 없다.
2. **종목 추가 폼**: 수량을 적고 목표 비중을 비운 채 추가하면, 추가 완료 알림에 "목표 비중을 비워 0%로 넣었습니다 — 리밸런싱에서 전부 팔기로 계산되니 목표를 넣으세요"를 더한다. 추가 완료 알림이 티커 대신 **이름**으로 말하게도 한다(점검 W7, 같은 줄).
3. 대시보드 빠른 입력 팝업(StockEditModal)은 이미 목표 칸이 보이므로 이번에는 손대지 않는다.

**데이터·호출**: 바뀜 없다. 화면만 바뀐다(`OrderLine`에 필드를 더하는지는 개발자가 고른다).
**화면 말**: 새 문구 둘. 용어집 "목표 비중" 줄에 더한다.
**완료 조건**:
- 시험: 보유·목표 0 → 꼬리 있음. 미보유·목표 0 → 없음. 목표 > 0 → 없음. 둘 이상이면 모은 줄. 매수만 보기 → 없음.
- 추가 알림 시험(수량 있고 목표 빔 / 목표 있음 / 수량 없음).
- 360×640에서 지인 데이터로 리밸런싱 첫 화면의 높이가 얼마나 느는지 전후로 잰다.

## 하지 않는 것
- **목표 비중 "미정" 상태**(DB에 null 허용). 마이그레이션이 필요하고, 0.45.x 배포 전에는 DB를 더 바꾸지 않는다.
- **세션 표(기기별 나가기 목록)**. 새 테이블이 필요하다. 이번에는 "모든 기기"만 한다.
- **Caddy 쪽 헤더나 본문 한도**. 앱 안에서 하면 PC와 서버에 같고 시험할 수 있다. Caddy는 Docker가 없어 시험할 수 없다.
- 점검의 2절(Postgres 복구 시험·pg_dump 타임아웃·health DB 확인), 3절 15~22번, 4절 기획 항목. 다음 라운드 후보로 ROADMAP 0-1에 옮긴다.
- 차트·숫자 칸 정교화.
