  4. **고쳐야 함: 확인 방법.** bat과 DEPLOY 대조 테스트는 둘이 같은지만 보고, 맞는지는 못 본다. 둘 다 이번에 같은 사람이 쓴다. 실제로 깨질 자리는 여기서 못 돈다. ssh로 비대화 실행할 때의 `docker compose exec` TTY 처리(`-T`가 필요하면 DEPLOY와 "글자까지 같게"가 성립하지 않는다), 작업 스케줄러의 첫 호스트키 질문과 키 암호 대기(`BatchMode=yes`), 키 경로의 공백, scp 실패 뒤에도 `--mark-pulled`가 찍히는지가 그렇다.
     제안: 서버 쪽 순서를 저장소의 셸 스크립트 하나로 옮긴다. 그러면 여기서 가짜 `docker`를 PATH에 두고 bash로 돌려 볼 수 있다. bat은 `ssh 한 줄 + scp 한 줄 + 성공 때만 mark`만 남긴다. 주인 확인 목록에는 "키 경로를 일부러 틀리게 → 진단에 표시가 안 생긴다"를 넣는다.
  5. **고쳐야 함: 서버 IP를 커밋할 위험.** 근거는 "서버 주소·키 경로는 bat 맨 위 두 줄"이라는 초안 문장이다. 추적되는 파일을 주인이 고치면 `git pull`이 충돌하고, IP를 실수로 커밋할 수 있다. 값은 무시 목록에 든 로컬 파일이나 첫 실행 질문에서 읽는다(`.gitignore`에 자리를 더한다).
  6. 참고: "30일 경고, 주인이 정할 숫자"를 어디에 두는지 없다(`.env` 이름인가?). 이것이 없으면 완료 조건을 확인할 수 없다. "(주인 PC)"는 서버가 알 수 없는 말이니 "밖에 꺼냈다는 표시"로 쓴다. 이미 `backup.bat`이 있어(PC 로컬 백업) `backup-pull.bat`과 헷갈린다. 용어집과 README에 차이를 한 줄 적는다.
