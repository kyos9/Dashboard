## A. 백업을 서버 밖으로 (고도화)

- **무엇**: "서버가 통째로 사라지면 백업도 같이 사라진다"(DEPLOY 10, `DEPLOY.md:371-372`)를 줄인다. 주인 PC 가 서버의 백업을 **당겨 오는** 파일 하나와,
  진단 화면에 "마지막으로 밖에 꺼낸 시각" 한 줄.
- **왜**: 0.44 에서 진단에 백업 상태는 생겼지만 "밖에 있나"는 모른다(`DiagnosticsModal.tsx:153`, DEPLOY 10 `:377`). 지금 꺼내는 길은 명령 넷을 손으로(`DEPLOY.md:380-390`).
- **길 고르기 (조사가 비교한 다섯)**:
  - (가) **주인 PC 가 당겨 가기** — 새 비밀·패키지 없음, 서버의 SSH 키를 그대로(이미 DEPLOY 에 있음), 제3자 없음 → 방침 3절 그대로. 약점: PC 가 켜져 있어야 한다(윈도우 작업 스케줄러로 주 1회).
  - (나) S3 호환 저장소(R2·오라클·B2) + 암호화 — 진짜 자동이지만 중간~큼: 서명 직접 구현, 암호화 키 관리, 방침 3절("다른 곳에 주는 것: 없습니다", `Policy.tsx:70-75`)·5절 고치기, 되돌리기 문서 다시 확인. 주인 계정·키 만들기가 필요하다.
  - (다) 이메일(25MB 한도로 곧 깨짐) · (라) 구글 드라이브(설정이 가장 어렵다) · (마) 다른 서버(서버 하나 더) — 권하지 않는다.
  - **초안은 (가)**. (나)는 다음 라운드 후보로 남긴다(주인이 "진짜 자동"을 원하면 이번에 바꿀 수 있다 → 주인 질문).
- **만드는 것**:
  1. 저장소 맨 위 `backup-pull.bat`(윈도우, PowerShell 의 `ssh`/`scp` — 윈도우 10 이상 기본): 서버에서 한 벌 뜨게 하고(`docker compose exec app python -m app.services.backup`), 컨테이너 밖으로 꺼내(`docker compose cp`), PC 의 정해진 폴더로 가져온다. 서버 주소·키 경로는 bat 맨 위 두 줄(비밀이 아니다 — 키 **파일 경로**만).
     가져온 뒤 서버에 표시를 남긴다: `docker compose exec app python -m app.services.backup --mark-pulled`(새 인자) → 백업 폴더의 상태 파일에 `pulled_at`.
  2. `backup.status()` 에 `offsite: {last_at}` **더하기**(필드는 더하기만). 진단 백업 줄 아래 "밖에 꺼낸 것: 마지막 10월 20일 (주인 PC)" / 없으면 "밖에 꺼낸 기록이 없습니다 — DEPLOY 10". 30일 넘으면 경고(주인이 정할 수 있게 숫자 하나).
  3. DEPLOY 10 을 bat 중심으로 다시 쓰고, 작업 스케줄러에 거는 법. 10-1(되돌리기)은 그대로 — 가져온 파일이 지금 손으로 꺼낸 것과 같은 파일이다.
- **데이터**: 새 표 없음. 상태 파일(`backup-status.json`)에 키 하나. 다시 만들 수 있다.
- **외부 호출**: 서버 쪽 0. **사람 수와 무관**.
- **화면 말**: 진단에 한 줄 새로. 용어집에 "밖에 꺼낸 백업".
- **부딪히는 결정**: 없음. "압축하지 않는다"(`backup.py:11-13`)는 그대로.
- **되돌리는 법**: bat 을 안 쓰면 지금과 같다. 진단 줄은 `offsite` 가 없으면(옛 서버) 숨긴다.
- **완료 조건**:
  - `--mark-pulled` 가 상태 파일에 시각을 남기고, `status()["offsite"]["last_at"]` 이 그것이다. 상태 파일을 못 쓰면 0.44 의 메모리 대체와 같게.
  - 진단: 기록 없음 / 있음 / 30일 넘음 세 상태가 화면 테스트로 있다. `offsite` 없는 옛 응답에서 줄이 숨는다.
  - bat: 여기서는 윈도우가 없어 못 돌린다 → **주인 확인 목록**. 대신 bat 이 부르는 명령 넷을 가짜 서버가 아니라 실제 `docker compose` 문법으로 DEPLOY 와 글자까지 같게(테스트가 bat 과 DEPLOY 의 명령 줄을 대조).
  - 비밀: bat·상태 파일·응답에 키 내용·비밀번호가 없다.

## B. 알림 조용한 시간 · 종목별 끄기 (고도화·사용자화)

- **무엇**: 🔔 알림 설정(`PushModal.tsx:172-193`)에 둘을 더한다.
  - **조용한 시간**: "이 시간에는 보내지 않고, 끝난 뒤 다음 판정 때 모아 보냅니다". 한국 시간 고정.
  - **종목별 끄기**: 종목마다 매수·비중 알림을 끈다(리뷰일 알림은 종목 단위가 아니라 그대로).
- **왜**: 0.44 계획에서 주인이 0.45 로 미룬 것(ROADMAP 0-1). 지금은 종류(매수·비중·리뷰)만 끌 수 있다.
- **사실 (조사)**:
  - 알림이 실제로 가는 때는 KST 07:30 · 16:00 · 16:30 과 서버를 켤 때뿐이다(`scheduler.py:284-295`, `:127-128`). 그래서 "조용한 시간"이 실제로 막는 것은 아침 07:30 한 번과 재시작 때의 알림이다.
  - "미루기"가 "버리기"보다 쉽고 안전하다 — 조용한 시간인 사람은 그 판정을 건너뛰어(상태를 안 적음) 다음 판정 때 모아 간다(`alerts.py:293-294`). 대신 07:30 을 덮으면 16:00 에 간다 — 화면에 적는다.
  - 끈 종목도 상태는 계속 적는다(지금 "종류 끔"과 같은 약속, `alerts.py:11-12`) — 다시 켰을 때 지난 알림이 쏟아지지 않게. 다시 켤 때는 11-2 의 `record_buy_state_quietly` 처럼 조용히 적는다.
- **데이터**: `user_settings.push_prefs` JSON 칸 하나(사용자별, 다시 만들 수 있다 — 설정이다). `{"quiet": {"start": "22:00", "end": "08:00"} | null, "muted": ["VOO", …]}`.
  마이그레이션 **0015**: 칸 더하기(0013 본보기, `batch_alter_table`), 내리면 칸만 사라짐 — `DATA_ON_DOWNGRADE` 아님. 옛 이미지는 모르는 리비전으로도 뜬다(0.42~).
  `push_kinds`(list)·`signal_thresholds`(기준 판과 묶임)에는 섞지 않는다.
- **API**: `GET/PUT /api/push/settings` 에 `quiet`·`muted` 더하기. **PUT 에서 빠진 칸은 그대로**(옛 화면은 `kinds` 만 보낸다 — 테스트). 서버 검사: 시각은 30분 단위 `HH:MM`, 시작=끝 거절, `muted` 는 30개 이하 + 내 목록의 티커만, 모르는 키 거절.
- **화면**: 조용한 시간 켜기 + 시작·끝 고르기(30분 단위 고르기 상자). 종목별 끄기는 같은 팝업 아래 "종목별" 접힘 칸에 내 종목 목록 체크(종목 관리 화면을 고치지 않는다 — 서버 변경이 가장 작은 자리).
  종목을 지우면 `muted` 에서도 뺀다(읽을 때 내 목록에 없는 티커는 무시 + 저장할 때 정리).
- **외부 호출**: 늘지 않는다(오히려 준다).
- **방침**: "알림을 켜면 받을 알림 종류를 저장합니다"(`Policy.tsx:54-55`) → "받을 알림 종류·조용한 시간·끈 종목". `POLICY_EFFECTIVE` 바꾸기.
- **화면 말**: 새로 "조용한 시간", "종목별 알림". 용어집.
- **부딪히는 결정**: ROADMAP 6-1(바뀐 순간에만, 종류는 사람마다) — 지킨다. 11-2(기준을 바꾼 순간 조용히 적기) — 같은 방식.
- **되돌리는 법**: 기본값 `null`/`[]` 이면 지금과 같다. 0015 는 내려도 잃는 것이 설정뿐.
- **완료 조건**:
  - 조용한 시간 안의 사람은 그 판정에서 알림이 안 가고 상태도 안 적힌다 → 다음 판정에서 모아 간다(시각을 고정한 테스트, 자정을 넘는 22:00~08:00 포함).
  - 끈 종목의 buy/band 는 안 가고 상태는 적힌다. 다시 켜면 지난 상태로 알림이 쏟아지지 않는다.
  - 옛 화면의 PUT(`kinds` 만) 이 `quiet`·`muted` 를 지우지 않는다. 옛 서버(필드 없음)에서 새 화면이 두 칸을 숨긴다.
  - 입력 한도(시각 형식·개수·남의 티커) 422. 격리 표 그대로(경로가 늘지 않는다). 0015 를 SQLite·Postgres 에서 실제 모양 데이터로 올리기·내리기.

## C. 차트 팝업에 매도 근거 (정교화) — 규제 영향 있음(문구)

- **무엇**: 카드에서 여는 차트 팝업(`ChartModal.tsx:265-270`)은 지금 "매수 조건 n/4 + 칩"만 보인다. 그 아래에 **어깨매도(참고) 조건 셋의 오늘 판정**을 같은 모양으로 한 줄 — "어깨매도 조건(참고) 2/3 · 50일선 위 ✓ · ADX 상승 ✓ · 거래량 강함 ·".
- **왜**: 디자인 2차가 화면만으로는 못 한다고 키우기 후보로 넘긴 것(`docs/design/2차-정돈/끝-보고.md:54,90`), 0.44 계획에서 0.45 로 미룬 것(0.44 `plan.md:59`).
- **사실 (조사)**: 매도 조건 키 셋은 규칙에 데이터로 있다(`signal_rules.py:296-339`). 막힌 곳은 "50일선 위"가 **종가**를 쓰는데 오늘 조건 표에 종가가 없다는 것(`signals.py:20-24`) → 대시보드가 이미 읽는 종가(`dashboard.py:40`)를 지표 날짜에 맞춰 붙이는 새 길(`sell_conditions_many`).
  배지(`shoulder_sell_ref`)와 **같은 함수·같은 기준**(내 기준 포함)이어야 둘이 어긋나지 않는다.
- **데이터·API**: 카드 응답에 `sell_conditions`(더하기만). 새 표 없음. 외부 호출 없음.
- **화면**: 팝업에만. **카드에는 넣지 않는다**(폰 카드가 이미 길다 — 0.44 사용자 검토). 옛 서버(칸 없음)면 줄을 숨긴다.
- **규제 영향**: 이미 뜨는 "매도 시그널(참고)"의 근거를 보이는 것이라 새 판단은 없다. 다만 **문구**:
  - 상태로 쓴다("조건 2/3 충족"). "팔 때", "매도하세요", "줄이기" 같은 명령·권유는 쓰지 않는다.
  - 이름은 "(참고)"를 붙인 채로(`spec_name="어깨매도 (참고)"`).
  - 신호등 풀이의 "실제 매도 실행일은 리뷰 마감일입니다"(`display.ts:281`)는 팝업에 옮기지 않는다.
  - → 주인이 문구 전·후를 보고 정한다.
- **화면 말**: 새 줄 하나. 조건 이름은 `GET /api/signal-rules` 의 매도 규칙 이름을 그대로(화면이 새로 짓지 않는다).
- **부딪히는 결정**: 0.44 B(시그널/비중 두 줄) — 이 줄은 "시그널" 쪽이다. 3절 단정·추천 금지.
- **되돌리는 법**: 필드를 무시하면 지금과 같다.
- **완료 조건**: 기본 기준·내 기준 각각에서 `sell_conditions` 의 "다 충족"과 `shoulder_sell_ref` 가 모든 데모 종목·여러 날에서 같다(일치 테스트). 옛 응답에서 줄 숨김. 폰 360 에서 팝업 첫 화면 안에 차트가 남는다. 규제 단어 0.

## D. 작은 고치기 묶음 (정교화)

조사가 "사실인지"를 확인했다. 여섯 모두 작음, 화면 말이 바뀌는 것은 전→후를 적었다.

| D1 | 시그널 기준 저장의 오류가 "입력값은 올바르지 않습니다" | 서버가 모델 단위 검사라 오류 위치가 `body`, 칸 이름은 msg 안(`schemas.py:193-211`) · `FIELD_LABEL` 에 네 칸 없음(`client.ts:86-95`) | → "입력값을 확인해 주세요 — ADX 기준: 10 ~ 40 사이여야 합니다". 서버 문구는 그대로, 화면이 바꾼다 |
