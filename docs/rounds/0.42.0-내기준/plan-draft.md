## A. 시그널 기준 내 설정 (사용자화, 큼)

**무엇** (주인 말): 시그널 기준을 사람마다 — ADX 20 · 거래량비 1.1 · 이격도 0 · 비교 5거래일을 내가 바꾼다.

**왜**
- 0.41.0 에서 기준이 한 곳(`signal_rules.py`)에 모였고, 그 위에 얹으라고 남겨 둔 후보다(ROADMAP 0-1).
- 주인이 "시그널 로직은 언제든 변경할 수 있다"고 했다. 공용 정의를 바꾸기 전에 **내 화면에서만 먼저 바꿔 보는** 길이 된다.
  공용 정의 변경(배포·재계산·비교 도구)보다 훨씬 가볍다.

**공용 정의 변경과 다른 일이다** (§지켜야 할 선 "그대로 두는 것" 셋째 줄)
- 공용 `signal_daily` 는 바꾸지 않는다. 재계산·지문·`signal_diff` 도 그대로다.
- 내 기준은 **읽을 때 계산**한다. 공용 지표(`indicator_daily`)에 내 기준값을 대어 판정만 다시 한다(ROADMAP 1절 "싼 개인화").
- 기준값을 고르지 않은 사람(기본)은 **지금과 똑같은 길**(저장된 `signal_daily`)을 탄다. 응답 사진과 같아야 한다.

**바꿀 수 있는 값** — 0.41.0 의 상수 넷

| 값 | 기본 | 쓰는 조건 | 받는 범위 (안) |
| --- | --- | --- | --- |
| ADX 기준 `ADX_TREND` | 20 | 매수 "추세 형성" | 10 ~ 40, 0.5 단위 |
| 거래량비 `VOL_RATIO_EXPAND` | 1.1 | 매수 "변동성 또는 거래량", 매도 "거래량 강함" | 0.5 ~ 3.0, 0.05 단위 |
| 이격도 기준 `DISPARITY_BELOW` | 0 | 매수 "이격도 음수" | −20 ~ +5 (%) |
| 비교 기간 `LOOKBACK_DAYS` | 5 | 매수 "변동성 축소"(StdDev20 이 N일 전보다 작다), 매도 "ADX 상승"(N일 전보다 크다) | 1 ~ 20 거래일 |

- 조건의 **개수·종류는 바꾸지 않는다.** 그건 공용 정의 변경이다.
- 범위 밖·숫자가 아닌 값·모르는 키는 서버가 400 으로 막는다(§운영 규칙 "새 입력의 한도").

**데이터**
- 새 컬럼 하나: `user_settings.signal_thresholds` (JSON, nullable). **사용자별**.
  - `NULL` = 기본(지금과 같음). 값이 있으면 바꾼 키만 담는다(`{"adx_trend": 25}`).
  - 다시 만들 수 있나: 사용자가 넣은 값이라 아니다. 다만 작고, 잃어도 기본값으로 돌아갈 뿐이다. 백업에 들어간다.
- 마이그레이션 **0013** — nullable 컬럼 하나 더하기. 내리면 컬럼을 지운다(기준값만 잃고 다른 데이터는 그대로).
  두 DB(SQLite·Postgres)에서 실제와 같은 모양의 데이터를 넣고 올리기·내리기 테스트.
- 공용 표(`indicator_daily`·`signal_daily`)는 건드리지 않는다.

**계산**
- `signal_rules.py` 의 상수 넷을 `Thresholds` 값 하나로 묶는다. 평가 함수가 그것을 받는다(기본은 지금 상수).
  조건 문구(`label`·`header`·`formula`·AI 줄)도 그 값으로 만든다.
- 기본값이면 **지금 길 그대로**: 대시보드·차트·알림·AI 가 `signal_daily` 를 읽는다. 바꾼 사람만 `indicator_daily` 에서 다시 판정한다.
- 다시 판정에 드는 것: 종목마다 지표 행을 읽어 numpy 로 평가(0.41.0 의 `buy_conditions_many` 와 같은 방식). 바깥 호출은 없다.
  사람 수만큼 곱해지는 것은 **DB 읽기와 계산**뿐이다.

**내 기준이 쓰이는 곳 — A-결정 1** (주인이 정한다)

| 자리 | 지금 읽는 것 | 안 |
| --- | --- | --- |
| 대시보드 카드: 오늘 매수·매도, 조건 ✓, 마지막 매수 시그널 날짜 | `signal_daily` | 내 기준 |
| 시그널 보기 설명 줄·열 머리·칩·신호등 | `/api/signal-rules` | 내 기준 숫자로 |

- 추천: 표의 "내 기준" 칸 전부. 한 사람 화면 안에서 카드·차트·알림·리밸런싱이 같은 기준을 말해야 한다.
  일부만 따르면 "카드에는 매수인데 차트에는 점이 없다"가 된다.

**A-결정 2: AI 종목 분석·진단의 기준** (주인이 정한다)
- ㉠ 내 기준을 따른다 (추천) — 지시문의 규칙 문장도 내 숫자로("ADX > 25"). AI 에 새로 가는 것은 **기준 숫자 넷뿐**이다(보유·금액 아님).
  "보내는 내용 보기"에 그대로 보인다. 개인정보처리방침은 바꿀 것 없음(AI 로 가는 것은 이미 "보내는 내용 보기" 그대로라고 적혀 있음 — 계획 검토에서 확인).
- ㉡ 공용 기준 그대로 — AI 는 기본 기준으로 말하고, 화면에 "AI 는 기본 기준으로 봅니다" 한 줄. 화면과 AI 가 다른 판정을 말할 수 있다.

**화면**
- **고르는 자리**: 시그널 보기 설명 줄 끝에 "기준 바꾸기" 버튼 → 팝업(`SignalThresholdsModal`).
  - 넷의 입력 칸. 칸마다 기본값과 쉬운 풀이("ADX 가 이 값보다 크면 '추세가 있다'로 본다").
  - **"기본값으로"** 버튼 한 번에 넷 다 되돌린다(서버 값 `NULL`).
  - 저장하면 카드·차트가 내 기준으로 다시 그려진다.
  - 메뉴(⋯)에도 "시그널 기준" 한 줄 — 설명 줄을 못 찾는 사람용.
- **내 기준 표시**: 바꾼 사람에게는
  - 설명 줄 맨 앞에 "내 기준" 표시, 신호 요약 카드에 "내 기준으로 본 판정" 한 줄.
  - 차트 팝업의 시그널 설명에도 "내 기준".
  - 기본인 사람에게는 아무것도 더 나오지 않는다(화면이 지금과 같다).
- 숫자 입력은 기존 `NumberInput` 을 쓴다. 44px, 폰 360 에서 한 줄에 칸 하나.

**API** (모두 응답 필드 더하기만)
- `GET /api/signal-thresholds` · `PUT /api/signal-thresholds` · `DELETE /api/signal-thresholds`(기본값으로). 본인 것만 — `test_isolation.py` 표에 (USER, USER).
  - PUT 은 바꾼 키만 받는다. 기본값과 같은 값은 저장하지 않는다(모두 같으면 `NULL`).
- `GET /api/signal-rules` 응답에 더함: `custom: bool`, `defaults: {...}`. 규칙 문구는 **요청한 사람의 기준**으로.
- 카드의 `signal_rules_version` 은 "정의 지문 + 내 기준"의 지문 → 기준을 바꾸면 화면이 규칙을 다시 받는다(0.41 장치 그대로).

**옛 화면 ↔ 새 서버, 새 화면 ↔ 옛 서버**
- 0.41.0 화면(캐시)은 `/api/signal-rules` 로 문구를 받으므로 내 기준 숫자가 그대로 나온다.
- 0.40.0 화면(캐시)은 문구가 굳어 있다. 그 화면으로는 기준을 바꿀 수 없으므로, 바꾼 사람은 이미 새 화면이다. 남는 틈: 기기 둘 중 하나만 옛 화면 → 숫자 문구만 다르다(판정 값은 서버가 준 것). 참고로 적는다.
- 새 화면 ↔ 0.40.0·0.41.0 서버: `/api/signal-thresholds` 가 404 → "기준 바꾸기" 버튼과 메뉴 줄을 숨긴다. 화면 테스트로 확인.

**성능**
- 기본인 사람: 시작 수치와 같아야 한다(쿼리 수 그대로).
- 바꾼 사람의 대시보드: "마지막 매수 시그널 날짜"가 히스토리 전체를 다시 판정해야 한다(20종목 × 10년 ≈ 5만 행 읽기).

- 알림 판정은 하루 몇 번이고 사람 × 종목의 최근 N+1 행만 본다.

**규제 영향**: 없음.

**부딪히는 결정**: ROADMAP 1절(개인화 — 지표 공용, 판단 사용자별, 자유 입력 지표 기간은 안 받음).

**B-결정 1: 새로 넣을 돈** (주인이 정한다)
- ㉠ 안내 글만 바로잡는다 — "새로 넣을 돈까지 더한 전체 자금으로 목표 비중을 다시 맞춥니다". 동작은 명세 6.4 그대로.
- ㉡ ㉠ + **"팔지 않고 새 돈만 나누기"** 보기를 더한다 (추천) — 켜면 매도 없이 모자란 종목에만 새 돈을 나눈다(모자란 만큼 비례, 합 = 새 돈).
  기본은 꺼짐(지금과 같음). 명세 6.4 에 한 단락 더함. 기기에 기억.
- ㉢ 새 돈을 넣으면 ㉡ 을 기본으로 — 지금과 결과가 달라진다(§운영 규칙 "기본값은 지금과 같게"에 걸려 "뒤집기").

**B-결정 2: 소수 주** (주인이 정한다)
- ㉠ 그대로 — 수량이 소수인 사람도 있다(9-2).
- ㉡ 주문 가이드만 정수 주로 보이고 소수는 작게 덧붙인다 ("62주 (62.17)") (추천) — 금액·비중 계산은 그대로.
- ㉢ 시장별: 국내·일본은 정수 주(내림), 미국은 소수 그대로 — 증권사마다 미국 소수 주 거래 여부가 달라 앱이 단정하기 어렵다.

**데이터·API**: B 는 새 컬럼·엔드포인트 없음(B6 ㉡ 을 고르면 요청에 선택 필드 하나 — 없으면 지금처럼).
**규제 영향**: 없음. B5 는 등락 방향 색이지 사라·팔아라 색이 아니다(지금 가격 칸과 같은 규칙).
**되돌리는 법**: 커밋 되돌리기. B6 ㉡ 은 보기를 끄면 지금과 같다.
**응답 사진**: B1 은 `/api/signal-rules` 의 문구만 바꾼다(기준 다섯 경로에는 없다). B2·B9 가 서버를 고치면 그 차이는 원인과 함께 판정에 적는다.
