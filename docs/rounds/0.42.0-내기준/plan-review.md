# 0.42.0 계획 검토 — 검토자 (읽기만, HEAD 9135edb)

요지: **막음 1** (A 되돌리는 법이 틀림), **고쳐야 함 7**. 규제 선(B5·B6㉡)은 지금 쓴 대로면 닿지 않는다.

## A. 시그널 기준 내 설정
**찬성**
- 데이터 경계가 맞다. 기준값은 사용자별 `user_settings`에 두고, 공용 `indicator_daily`에서 읽을 때 계산한다. ROADMAP.md:153에서 "비교 기간(5일)"을 **싼 개인화**로 이미 적어 두었다. 그래서 1~20일은 지표 기간이 아니고, 미리 계산할 것도 없다(확인함).
- 바깥 호출이 늘지 않는다. 사람 수만큼 늘어나는 것은 DB 읽기와 numpy 계산뿐이다.
- 규제상 위험을 낮추는 쪽이다(ROADMAP 1절 덤 "사용자가 정한 규칙"). 백테스트 수익률과 "공격적·추천" 프리셋을 막는 줄도 들어 있다.

**걱정**
1. **막음 — 이미지를 되돌리면 앱이 안 뜬다.** 계획의 "0.41.x 이미지로 되돌려도 컬럼이 남아 무시"는 사실이 아니다. 옛 이미지는 DB에 찍힌 `0013`을 모른다. 그래서 켜질 때 `upgrade_to_head`가 `pending_revisions(stamped)`를 부르고(app/migrate.py:104-105) 여기서 예외가 난다. 직접 확인했다: `migrate.pending_revisions('0013')` → `ResolutionError No such revision or branch '0013'`. DEPLOY.md:273-283의 `IMAGE_TAG` 되돌리기도 같은 데서 막힌다. 고칠 길은 둘이다. (가) 새 이미지에서 `downgrade 0012`를 먼저 하는 순서를 DEPLOY와 끝 보고에 적는다. (나) 앞선 리비전을 만나면 경고만 하고 뜨게 한다(이것도 다음 라운드부터만 효과가 있다). 어느 쪽이든 실제로 되돌려 보는 테스트를 하나 둔다.
2. **고쳐야 함 — A-결정 2가 실제 코드와 맞지 않는다.**
   - 시그널을 AI로 보내는 곳은 셋이다: `stock_job`(화면 이름 "AI 분석", ai_analysis.py:599), `watchlist_job`("AI 전체 정리", :604), `portfolio_job`(진단, ai_portfolio.py:189 `buy_today` · :175 `shoulder`).
   - 계획이 "AI 종목 분석"이라고 부른 `research_job`은 시그널을 보내지 않는다.
   - 계획은 "공용 AI 정리 — 모두에게 같은 글"이라고 썼지만, 정리 결과를 나눠 쓰는 캐시는 없다. 사람마다 자기 키로 부른다.
   - 그래서 ㉡을 고르면 이렇게 된다. 진단 하나 안에서 `shoulder`는 리밸런싱(A-결정 1 → 내 기준)에서 오고, `buy_today`는 `signal_daily`(공용)에서 온다. 두 기준이 한 지시문에 섞인다. 정리 화면은 카드와 다른 판정을 말한다.
   - 결정의 대상을 이 세 경로로 다시 적고, 경로마다 어느 기준인지 정해야 한다.
3. **고쳐야 함 — 방침을 고쳐야 한다. "바꿀 것 없음"이 아니다.**
   - (a) A-결정과 상관없이 수집하는 것이 하나 는다. Policy.tsx:43-44 "내가 입력한 것"에 "시그널 기준"을 더해야 한다(운영 규칙 "방침").
   - (b) ㉠이면 Policy.tsx:71-73 "그 종목의 **공용** 데이터(…시그널…)"가 틀린 말이 된다. 정리에 내 기준 판정과 숫자가 들어가면 PROMPT "AI — 정리: 공용 숫자만"을 넓히는 것이다. 이 경우 세 가지(보내는 내용 보기·방침·규제 영향)를 같이 적고 주인이 정한다.
   - 참고: 방침에는 진단·분석(%를 보냄)이 아예 빠져 있다. 원래 있던 빈틈이다.
4. **고쳐야 함 — 공용 지문과 사용자 지문을 나눠야 한다.** `fingerprint()`는 공용 재계산을 이끈다(signal_recompute.py:49·102, admin.py:135, signal_diff.py:120). 카드의 판(dashboard.py:42)은 **새 함수**로 만들어야 한다. 기본 사용자는 지금 `fingerprint()` 값과 글자까지 같아야 한다(완료 조건 1의 응답 사진). 사용자 기준이 공용 지문과 재계산에 닿지 않는다는 테스트도 둔다.
5. **고쳐야 함 — 격리 표와 입력 한도가 지금 코드와 다르다.**
   - 표에 쓴 `(USER, USER)`는 틀렸다. `(MINE, USER)`다(test_isolation.py:64-70).
   - `GET /api/signal-rules`는 지금 `(SHARED, USER)`다(:101). 요청한 사람 기준을 돌려주게 되면 MINE으로 옮기고, A의 기준이 B에게 안 보이는지 확인해야 한다.
   - 앱에는 `extra="forbid"`·본문 크기 제한·`allow_inf_nan`이 하나도 없다(grep 0건). 모르는 키는 지금 조용히 무시된다.
   - 스키마 오류는 이 앱에서 **422**다(test_isolation.py:945 등). 완료 조건 5의 "400"을 하나로 맞춘다.
   - 따로 정해 둘 것: NaN·Infinity 거절, `true`가 `lookback_days`=1로 바뀌는 문제(strict), 1.5일 같은 소수 거절, 0.5·0.05 단위를 거절할지 반올림할지, 본문 크기를 어떻게 막을지.
6. **고쳐야 함 — 기준을 바꾼 직후 알림 정책이 없다.** `PushState`는 바뀐 순간에 울린다(alerts.py:150-170, 199-216). ADX를 10으로 낮추면 다음 판정에서 여러 종목의 "매수 시그널" 알림이 한꺼번에 간다. 저장했다 되돌렸다를 반복하면 또 간다. 다음 중 하나로 정한다: 바꾼 뒤 지금 상태를 알림 없이 기록만 한다 / 알린다 / 화면에 미리 알린다. `signal_diff`의 알림 세기에서도 내 기준을 쓰는 사람은 빠진다(참고).
7. **고쳐야 함 — 완료 조건 3이 실제로는 아무것도 확인하지 않는다.** PUT이 기본값을 `NULL`로 접기 때문에 "기본값과 같게 넣으면 같다"는 늘 참이다. 기본값을 DB에 직접 넣어 **읽을 때 계산하는 길을 강제로 타게** 한다. 그 결과가 `signal_daily` 전체 기간(데모 전 종목: 마지막 매수일·차트 점·리밸런싱 shoulder)과 같은지 본다. 판정 불가(NA)를 접는 방식이나 빈 날 처리가 어긋나면 여기서 잡힌다.
- 참고: 이격도 기준이 +5까지면 "종가가 MA20 아래"(signal_rules.py detail)나 키 이름 "음수"가 틀린 말이 된다. 문구를 값에서 만들거나 상한을 0으로 둔다. 메모리 캐시는 크기 한도를 둔다. 이미 남긴 리밸런싱 기록은 기준을 바꿔도 다시 계산하지 않는다.

**제안**: 경계값 데이터(ADX 22, 거래량비 1.2처럼 20↔25, 1.1↔1.3 사이에 걸치는 값)로 카드·차트·알림·리밸런싱 네 길을 한 테스트에서 본다. 그러면 "한 길에서만 기준을 빼먹는" 뮤테이션이 잡힌다.
