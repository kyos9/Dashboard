## A. 숫자 칸이 버린 글자를 말해 준다 — 중간

**무엇(주인 말로)**: 숫자 칸에 넣을 수 없는 글자(빼기표·소수점)를 치면 지금은 말없이 사라진다. "-3" 을 넣으면 3, "7.5" 를 넣으면 75 가 된다.
사라지는 대신 "이 칸에는 빼기(−)를 넣을 수 없습니다" / "이 칸은 정수만 받습니다 — 소수점을 뺐습니다" 를 칸 바로 아래에 잠깐 보인다.

**왜**: 0.44·0.45 사용자 확인 둘 다 잡았다. 거절이 아니라 **다른 숫자**가 저장되는 실패라 화면만 보고는 모른다(`NumberInput.tsx` 의 주석이
이미 그 위험을 적어 두었다 — 물가 예상치에만 막아 두었다). 특히 "7.5"→"75" 는 열 배다.

**지금 코드**: `frontend/src/components/NumberInput.tsx` — `parseNumeric(input, allowDecimal, allowNegative)` 가 버리고, 부르는 곳 31곳
(`grep -rn "<NumberInput" frontend/src --include=*.tsx | grep -v test`). 기본은 `allowDecimal=true`, `allowNegative=false`.
정수만 받는 칸: 원화 금액(`RebalancePanel` 476·1191 — 통화가 USD 가 아니면), 시그널 기준의 N거래일(`SignalThresholdsModal` FIELDS `decimal:false`).
빼기를 받는 칸: 물가 예상치(`MacroPanel` 199), 시그널 기준 하나(`negative:true`).

**하는 것**
1. `parseNumeric` 은 그대로 두고, 같은 입력에서 **무엇을 버렸는지**를 돌려주는 순수 함수를 더한다(`droppedKinds(input, allowDecimal, allowNegative)`
   → `'minus' | 'decimal'` 집합). 콤마·공백·"원" 같은 글자는 지금처럼 말없이 버린다(붙여넣기 "1,234원"을 받는 것이 이 칸의 일이다).
   - 빼기: 칸이 음수를 받지 않는데 사람이 친 글자에 `-`(또는 `−` U+2212, 붙여넣기)가 있으면
   - 소수점: 칸이 정수만 받는데 `.` 이 있으면. 칸이 소수를 받는데 소수점이 둘 이상이면 두 번째부터 버리는 것은 지금처럼 말없이(오타)
2. `NumberInput` 이 버린 것이 있으면 칸 바로 아래에 한 줄(`role="status"`, `aria-live="polite"`)을 보인다. 다음에 버리는 것 없이 고치면 사라진다,
   칸을 떠나면(blur) 사라진다. 칸의 값(부모에게 가는 문자열)은 **지금과 똑같다** — 저장되는 숫자는 바뀌지 않는다.
   - 배치: 칸을 `span.num-field`(position: relative, 칸과 같은 너비) 로 감싸고 줄은 절대 위치로 칸 아래에 띄운다 — 표·격자 안 31곳의 줄 높이를
     밀지 않으려고. 감싸는 것이 기존 CSS(`.num-input` 의 너비 규칙, `label > input` 같은 선택자)를 깨는지 31곳을 화면으로 확인한다.
   - 대안(개발자 검토에 묻는다): 감싸지 않고 `aria-invalid` + 칸 테두리 깜빡임 + 브라우저 기본 풍선(`setCustomValidity`/`reportValidity`) —
     아이폰 사파리는 풍선을 띄우지 않아 버렸다.
3. 문구(용어집에 더한다):
   - 빼기: "이 칸에는 빼기(−)를 넣을 수 없습니다"
   - 소수점: "이 칸은 정수만 받습니다 — 소수점을 뺐습니다"
   - 둘 다면 두 줄이 아니라 한 줄 "빼기(−)와 소수점은 넣을 수 없습니다"
4. 시험: `droppedKinds` 경계(빈 칸·"-"·"−3"·"7.5"·"1.2.3"(소수 칸: 말 없음)·"1,234원"(말 없음)·붙여넣기 "-1,234.5") ·
   `NumberInput` 렌더(줄이 뜨고, 고치면 사라지고, blur 에 사라지고, `onChange` 값은 지금과 같다) · 지금 동작을 굳힌 시험(`NumberInput.test.tsx`)은
   값 부분은 그대로 통과해야 한다.

**하지 않는 것**: 칸마다 범위 검사(0~100% 등)를 화면에서 새로 하지 않는다 — 서버가 이미 400 으로 돌려주고 화면이 보인다(지금 그대로).
밴드·수량에 음수를 **받게** 하지 않는다(음수 밴드·수량은 뜻이 없다).

**완료 조건**
- 31곳 모두에서 정수 칸에 "7.5", 음수 안 받는 칸에 "-3" 을 치면 칸 아래에 그 줄이 보이고, 저장되는 값은 지금과 같다(75 / 3 — 값은 바꾸지 않고 알린다).
  *(주인이 "값을 바꾸지 말고 막아라"를 원하면 보기로 — 아래 "주인에게")*
- 물가 예상치·음수 받는 시그널 기준 칸에서는 "-" 에 아무 줄도 뜨지 않는다. 소수 받는 칸에서 "1.2.3" 에도 줄이 뜨지 않는다.
- 1400·390·360 × 두 테마, 31곳이 있는 화면(종목 관리·일괄 수정·리밸런싱(거래 입력·현금·밴드)·대시보드 목표 비중·매크로 예상치·시그널 기준)에서
  가로 넘침 0, 줄이 다른 칸·단추를 가려 누를 수 없게 되는 곳 0, 콘솔 오류 0.
- 화면 읽기: 줄이 `role="status"` 로 읽힌다.

## D. 알림 설정 — 작음

**D1 "종목별 알림"에 모두 다시 켜기가 없다** (0.45 B 사용자 확인)
- 하는 것: 끈 종목이 하나라도 있으면 목록 위에 "모두 다시 받기" 단추 하나 → `muted: []` 로 저장(이미 있는 API, 새 필드 없음). 끈 것이 없으면 단추 없음.
  "모두 끄기"는 넣지 않는다(알림을 다 끄는 길은 이미 맨 위 스위치다).
- 완료 조건: 시험 — 단추를 누르면 `setPushPrefs({muted: []})`, 숨긴(비활성) 종목이 muted 에 남아 있던 경우도 같이 비운다(그게 "모두"의 뜻 — 0.45 B 검토의 "보이는 것만 센다"와 함께 적는다). 44px.

**D2 처음 온 사람(종목 0개)은 종목별 알림이 있는 줄 모른다** (0.45 B 사용자 확인)
- 지금: `stocks.length > 0` 일 때만 칸을 그린다.
- 하는 것: 종목 0개면 접힌 칸 대신 한 줄 "종목을 담으면 여기서 종목마다 알림을 끌 수 있습니다." (서버가 `muted` 를 보낼 때만 — 옛 서버면 지금처럼 없음).
- 완료 조건: 시험 — 종목 0개 + muted 있음 → 그 줄, muted 없음(옛 서버) → 없음.

**D3 확대 150%(933px)에서 종목 목록을 펼치고 끝까지 내리면 ✕ 가 화면 밖** (0.45 B 사용자 확인)
- 하는 것: 알림 설정 팝업이 화면 높이를 넘으면 머리(제목·✕)는 그대로 있고 몸통만 스크롤되게 한다(다른 팝업 — 진단 등이 이미 하는 방식이 있으면 그것을 따른다).
- 완료 조건: 933×(150% 배율) 와 360×640 에서 종목 20개를 펼쳐 끝까지 내려도 ✕ 가 보이고 눌린다(Playwright 확인, 스크린샷).
- 개발/디자인 경계: 배치만 바뀌지만 "닫을 수 없다"는 동작 문제라 이 라운드가 맡는다.
