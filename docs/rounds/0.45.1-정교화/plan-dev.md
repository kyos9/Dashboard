## A. 숫자 칸이 버린 글자를 말해 준다

**찬성**: 값은 그대로 두고 알리기만 하는 것(붙여넣기 "1,234원" 을 지킨다). `parseNumeric` 을 건드리지 않는 순수 함수 하나 더하기.

**걱정**
1. **고쳐야 함 — "다음에 고치면 사라진다"면 줄이 거의 안 보인다.** 버린 글자는 칸에 남지 않는다(`NumberInput.tsx:105` 가 걸러낸 값만 부모로 보내고 `:121` 이 그 값을 그린다). 그래서 "7.5" 를 치면 `.` 에서 줄이 뜨고, 바로 다음 `5` 에서는 입력에 버릴 것이 없어 줄이 사라진다. 빠르게 치는 사람은 못 본다. 화면 읽기도 곧바로 사라지는 줄은 읽지 않는다.
2. **고쳐야 함 — 감싸기(`span.num-field`)가 레이아웃을 깬다.** 너비와 flex 규칙이 모두 *input* 에 걸려 있다. 감싸면 flex 항목이 input 에서 span 으로 바뀌어 이 규칙들이 효과를 잃는다.
   - `index.css:1969-1972` `.input-with-button input { flex: 0 1 108px }` 과 `:1988-1992` `.tight input { flex: 1 1 auto; width: auto; min-width: 64px }`. `width: auto` 인 input 은 제 크기(약 20글자)로 커지고, 감싼 span 은 그보다 줄어들지 못한다. `tight` 를 쓰는 곳은 표 칸(Dashboard 1398·1408, RebalancePanel 194–321)과 `StockEditModal` 339–368 이다.
   - `index.css:1861` `input[type=text] { width: 100% }` 와 `:3055` `.forecast-form input`, `:4722` `.stock-edit-fields .num-input` 도 퍼센트 너비라 감싸는 span 의 표시 방식(인라인/블록)에 따라 결과가 달라진다.
   - 절대 위치로 띄운 줄은 `.table-scroll { overflow-x: auto }`(`:1163`, 대시보드·리밸런싱 표)와 `.modal { overflow-y: auto }`(`:2114`) 안에서 마지막 줄 아래가 잘리거나 칸 안에 스크롤을 만든다. `sticky-first` 표에서는 고정된 첫 칸 밑에 깔린다.
3. **고쳐야 함 — `−`(U+2212)와 음수를 받는 칸.** 음수를 받는 칸에서도 `parseNumeric` 은 맨 앞의 `-` 만 본다(`:41`). 그래서 물가 예상치에 "−0.2"(붙여넣기)나 "0.2-" 를 넣으면 말없이 0.2 가 된다. 이 파일이 막으려던 바로 그 실패인데, 초안의 `droppedKinds` 는 "칸이 음수를 받지 않을 때"만 빼기를 센다.
4. 참고 — 셈이 틀렸다. 부르는 줄은 31곳이 아니라 **26줄**이다(map 안이라 그려지는 칸은 더 많다). 정수만 받는 칸은 **3곳뿐**이다: `RebalancePanel.tsx:476`·`:1191`(USD 가 아닐 때), 시그널 N거래일. 그래서 사용자 과업의 "원화 거래 가격에 7.5" 는 틀렸다. `RebalancePanel.tsx:208` 은 기본값인 소수 칸이라 줄이 뜨지 않는다.
5. 참고 — 아이폰에서는 `inputMode` 가 `decimal` 이면 키패드에 빼기가 없고, `numeric` 이면 점이 없다(`:117`, 부르는 쪽의 `inputMode` 도 덮어쓴다). 그래서 아이폰에서 이 줄은 거의 붙여넣기에서만 뜬다. 같은 이유로 물가 예상치와 음수를 받는 시그널 칸에는 아이폰에서 빼기를 칠 수 없다. 지금도 있는 문제이고, 이번 범위 밖이면 다음 후보로 둔다.
6. 참고 — `setCustomValidity` 를 버린 결정은 맞다. iOS 사파리가 풍선을 띄우는지는 확실하지 않아서 실기기 확인이 필요하다. 하지만 띄우더라도, 치는 도중에 `reportValidity` 를 부르면 풍선이 잠깐 떴다 사라지고 칸마다 다르게 보인다.

**제안**
- 줄을 **판정 기준과 수명으로** 정한다.
  - 판정: 입력에 `-`/`−` 가 있는데 결과가 `-` 로 시작하지 않으면 "빼기를 버렸다", 정수 칸에 `.` 이 있으면 "소수점을 버렸다". 이렇게 하면 걱정 3 의 칸도 같은 함수로 잡힌다.
  - 수명: 한 번 뜨면 약 4초 또는 blur 까지 남는다. 같은 것을 또 버리면 시간을 다시 잰다. 시험도 "다음 깨끗한 글자에 사라진다" 대신 "다음 글자에도 남고, blur 에 사라진다"로 바꾼다.
- **감싸지 않는 길**: 줄을 `createPortal` 로 body 에 `position: fixed` 로 그리고, 칸의 `getBoundingClientRect()` 바로 아래에 둔다. `pointer-events: none` 을 주고, blur 나 스크롤 때 숨긴다. 화면 읽기에는 앱에 하나만 있는, 늘 붙어 있는 `role="status"`(sr-only) 에 같은 말을 넣는다. 그러면 26곳의 CSS 와 표 잘림을 건드리지 않는다. 늘리는 코드는 30줄 안팎이다.
- 감싸는 길을 고르면: `.num-field` 를 `display: flex` 로 두고, flex·너비 규칙을 `.input-with-button > .num-field` 로 옮긴다(위 1969·1988·3055·4722). 줄에는 `pointer-events: none` 을 준다. 표 마지막 행에서 잘리는 것은 남는다.

## B1. 차트 두 번 탭

**찬성**: 원인 짐작이 맞다. 손가락은 `touchend`(`mjs:8240-8253`), 마우스는 `mouseup`(`:8293-8306`)에서 갈린다. 500ms 안의 두 번째 누름은 `doubleTap`/`dblclick` **하나만** 보내고 tap/click 은 보내지 않는다. 그다음 `resetTapTimeout`(`:8123`)으로 셈을 0 으로 되돌린다. iOS 의 dblclick 경로(`:8040-8051`)도 같은 셈을 쓰므로 둘이 겹쳐 오지 않는다. 겹쳐 오더라도 처리기는 같은 자리·같은 값을 다시 넣을 뿐이라 해가 없다. 인자도 click 과 같은 모양으로 온다(`:9931-9935` — x 를 index 로 바꾼 값).

**걱정**
1. 고쳐야 함 — **두 번째 탭이 30px 이상 떨어져 있으면 아무 것도 오지 않는다.** 마우스는 5px 이다(`:8245`·`:8297`). 거리를 넘으면 셈은 1보다 크지만 doubleTap 은 보내지 않고, 그냥 셈을 0 으로 되돌린다. 그래서 dblClick 을 받아도 "0.5초 안에 다른 날을 누른다"는 여전히 무시된다. 초안의 Playwright 확인(0.3초 간격 두 탭, 두 번째 날짜)은 두 탭을 30px 안에 두어야만 통과한다.

**제안**: 완료 조건에 "30px 안(같은 근처)"을 적는다. 30px 이상 떨어진 두 탭이 무시되는 것은 라이브러리의 성질로 status 에 남긴다. 그것까지 고치려면 `subscribeCrosshairMove` 가 아니라 컨테이너의 `pointerup` 을 직접 받아야 해서 이번 크기를 넘는다.

## B2. 없는 종목 주소

**찬성**: 서버 문자열은 그대로 두고 화면에서 말을 바꾸는 것.

**걱정**
1. **고쳐야 함 — 숨긴 종목은 지금 차트가 나온다.** 서버는 숨긴 종목도 돌려준다(`history.py:43` → `users.py:130`, active 거르지 않음). 초안대로 하면 되던 것을 막는다(옛 화면은 열리고 새 화면은 막히는 회귀).
2. 고쳐야 함 — **경쟁**: 두 effect 가 마운트 때 같이 돈다(`HistoryChart.tsx:24`, `:38`). `stocks` 의 처음 값 `[]` 은 "아직 안 받음"과 "0개"를 가르지 못한다(`:15`, `:49` — 지금도 받는 동안 NoStocksYet 가 잠깐 뜬다). 시세를 목록 뒤로 미루면, 있는 종목도 요청이 줄줄이 이어져 한 번 왕복만큼 늦어진다.
3. 고쳐야 함 — 서버는 ticker 를 대문자로 바꾼다(`history.py:37`). 화면이 `s.ticker === ticker` 로 대조하면 `?ticker=nvda` 가 "담은 종목에 없습니다"가 된다(지금은 차트가 나온다).

**제안**: `stocks: Stock[] | null`(받기 전 null)과 숨긴 종목 집합을 둔다. 대조는 대문자로 한다. 시세는 지금처럼 같이 부르고, 판단은 **그릴 때** 한다.
- 목록을 받았는데 담은 종목에 없으면 error·history 를 버리고 그 문장을 보인다. 범례와 Coverage 는 그리지 않는다.
- 숨긴 종목이면 차트는 그대로 보이고, 위에 "숨긴 종목입니다…" 한 줄만 단다.
- 0개면 ticker 와 상관없이 NoStocksYet 가 먼저 나온다(지금은 0개 + NOPE 면 "stock not found" 가 뜬 빈 화면이다).
- 시험의 "시세를 부르지 않는다"는 "stock not found 가 안 보인다"로 바꾼다.

## C1. 진단 요약과 백업

**찬성**: 요약이 무엇을 세는지 말하는 것.

**걱정**
1. 고쳐야 함 — **`backup_attention` 은 쓰지 말 것.** 이 값은 `/api/auth/status` 에서 구글 모드의 관리자에게만 온다(`auth.py:196-201`). 페이지를 열 때 한 번 읽고 남아 있는 값이고(`AuthGate.tsx:176`), 혼자 쓰는 PC 모드에는 없다. 그런데 PC 모드의 백업 칸에도 경고 줄(멈춤·실패)은 뜬다. 진단 팝업은 이미 `records.status.backup` 을 받는다(`DiagnosticsModal.tsx:226-231`, `:212`).

**제안**: `BackupLines` 의 세 조건(`:150` stale, `:168` last_failure, `:187` offsite 30일)을 순수 함수 `backupWarnings(backup, now)` 로 꺼내 둘이 같이 쓴다. 그러면 "백업 칸에 경고 줄이 있으면"과 요약이 늘 맞는다. 옛 서버(`backup` 없음)나 records 실패면 붙이지 않는다. `DiagnosticsModal.test.tsx:109-120` 의 옛 문구는 고친다.

## C2. 앱이 꺼졌을 때의 백업 꺼내기 (이미 `320ed0c`)

**찬성**: exec 실패와 "목록 비어 있음"을 가른 것, 시험 `test_backup_export_script.py:103`.
**걱정**: 참고 — `ls -1 /data/backups` 는 폴더가 아직 없을 때(새 서버에서 첫 백업 전)도 실패한다. 그때도 "앱이 꺼져 있다"고 말한다(`backup-export.sh:29`). `backup.py:223` 이 첫 백업 때 폴더를 만든다.

## D1. 모두 다시 받기

**찬성**: `muted: []` 는 서버 모양 그대로 된다. `mine` 이 숨긴 종목까지 포함하므로(`push.py:66`, `:107` — active 를 거르지 않음) GET 의 `muted` 에 숨긴 종목도 오고, `[]` 를 보내면 숨긴 것까지 비운다. 그러면 기본값이라 `push_prefs = None` 이 된다(`:117`). 73줄의 "내 목록에 없는"은 *지운* 종목을 말한다.
**걱정**: 고쳐야 함 — **언제 보이나가 둘로 읽힌다.** `settings.muted.length > 0` 을 기준으로 하면, 숨긴 종목만 끈 사람에게는 요약이 "모두 받음"(`PushModal.tsx:272-273`)인데 단추가 같이 뜬다. 참고로, 누른 뒤 단추가 사라지면 키보드 포커스가 body 로 빠진다.
**제안**: 단추는 *보이는* 끈 수(`off > 0`)로 띄우고, 보내는 것은 `[]` 로 한다. 둘 다 계획에 적는다. 단추가 사라질 때는 포커스를 `summary` 로 돌린다.

## D2. 종목 0개

**걱정**: 고쳐야 함 — 목록 받기가 실패해도 `setStocks([])` 다(`PushModal.tsx:74`). 그래서 네트워크 오류에도 "종목을 담으면…"이 뜬다. 참고 — 숨긴 종목만 있는 사람(활성 0)에게도 같은 문장이 뜨는데, 이미 담은 사람에게는 틀린 말이다.

## muted 글자 길이 한도 — 넣는다(작음)

목록 개수만 막혀 있고(`push.py:43` 200개), 글자 하나하나에는 한도가 없다. 화면이 받는 한도(요청 본문 크기)도 없다. 400 답은 모르는 티커 5개를 **그대로** 되돌려 준다(`push.py:111-114`). `Field(max_length=…)` 를 원소에 걸면 FastAPI 422 가 `input` 을 또 되돌려 주므로, 지금처럼 400 한 줄 갈래를 쓴다.
- `len(t) > 32` 이면 400 "내 목록에 없는 종목입니다."
- 메시지에는 `t[:20]` 만 넣는다.
- 시험은 하나 더한다. 서버 2–3줄이다. 옛 화면은 긴 티커를 보내지 않으므로 호환에는 영향이 없다.
