# 0.44.0 계획 다시 보기 (바뀐 부분만) — 검토자

판정: **막음 0 · 고쳐야 함 4 · 참고 5**. 앞서 낸 걱정(개발자 1~6, 검토자 A1~A3)은 방향이 맞게 풀렸다. 아래 넷은 명세에 한 줄씩 더 적어야 할 것들이다.

## A 표
- **대상 `in_use`**: 찬성. `watched()` 와 같은 조건이라(pipeline.py:31-49, 92) 시세를 받는 사람과 기록하는 사람이 같아진다. 걱정(참고): 표에 적힌 "180일 안 들어온 사람"은 실제 조건보다 좁게 쓴 말이다. 주인, 로그인 기록이 없는 사람(로컬 모드), 알림 기기가 남은 사람도 들어간다(pipeline.py:43-50). 명세에는 "`in_use` 그대로"라고 적는다. 휴면이 된 동안은 기록이 비고 되살리지도 않는다는 것도 적는다. 보유와 현금이 다 0 이 된 사람은 빠지는데, 그러면 "0원"과 "기록 없음"이 구분되지 않는다. 전날 줄이 있으면 0 줄을 남기기를 제안한다(참고).
- **미국 갱신 잡 끝에 붙이기**: 찬성. 걱정(**고쳐야 함**): `_daily_refresh_job` 은 `_refresh` 만 부르고, `_refresh` 는 `refresh_all_active_stocks` 의 예외를 잡지 않는다(scheduler.py:44-51, 72-73). 그래서 끝에 그냥 이어 붙이면 갱신이 넘어진 날은 기록도 빠진다. 켤 때 잡에 정한 "실패해도 시도"를 매일 잡에도 똑같이 걸어야 한다(try/finally, 따로 세션). 참고: `date` 는 서버 시간대가 아니라 `Asia/Seoul` 로 잡는다(컨테이너는 UTC). 켤 때 upsert 는 그날 07:30 KST 의 줄을 낮의 값으로 덮어쓴다. 이건 괜찮지만, "그날 마지막으로 쓴 값"이라고 명세에 적는다.
- **내리기 백업 조건**: 찬성. 지금 `downgrade_to` 는 `required=False` 로 고정돼 있다(migrate.py:123). 그래서 "0014 를 건너면 `required=True`"로 갈래가 하나 필요하다. 걱정(참고): 그 백업은 `premigrate` 이름으로 매일 백업과 같은 7벌 순환에 들어가 7일 뒤 지워진다(backup.py:139-148, 36). DEPLOY 9-2 에 "내린 뒤 그 백업을 따로 옮겨 두라"를 한 줄 넣기를 제안한다.
- **탈퇴 테스트를 metadata 로 모으기**: 찬성. 걱정(**고쳐야 함**): "탈퇴 뒤 0행"만 보면, World 가 B 의 줄을 깔지 않은 표는 처음부터 0이라 그냥 통과한다. 지금 World 에도 그런 표가 있을 수 있다(test_isolation.py:770-772 는 손 목록, 263~ World). 그래서 **탈퇴 전에** 모은 표마다 B 의 줄이 1 이상인지 먼저 확인하고, `_a_is_untouched` 에도 새 표를 넣는다. 지우는 코드는 여전히 손 목록이다(auth.py:373). FK 순서는 Postgres 에서만 잡히니 CI 의 Postgres 칸에서 이 테스트가 도는지 확인한다(dbsetup.py:17-50).

## D0 진단에 백업 상태
- 찬성: 자리를 `/api/admin` 아래에 두면 `require_owner` 가 저절로 걸린다(admin.py:31). 그래도 경로 표에 `(SHARED, OWNER)` 로 한 줄 더한다(test_isolation.py:134-140).
- 걱정(**고쳐야 함**): **"마지막 실패 사유"는 지금 어디에도 남지 않는다.** `run_backup` 은 로그만 찍고 None 을 돌려준다(backup.py:144-148). 그래서 남길 자리를 새로 정해야 한다. 메모리에 두면 스케줄러를 맡은 프로세스에만 있어서(scheduler.py:259, leader), 다른 워커가 요청을 받으면 비어 보인다. 파일이나 DB 에 남기는 쪽을 명세에 적는다.
- 걱정(**고쳐야 함**): **경로를 숨기는 것과 실패 사유를 그대로 보이는 것이 부딪친다.** 예외 글에 경로와 접속 정보가 그대로 들어간다. `FileNotFoundError(f"...{source}")`(backup.py:105), `pg_dump` stderr(호스트·DB·사용자 이름, backup.py:93), `mkdir` 권한 오류(경로)가 그렇다. 사유를 고정된 분류(디스크·권한·pg_dump 없음·DB 파일 없음·기타)로 바꿔 보이고, 원문은 로그(주인 전용)에만 두기를 제안한다. 테스트로 응답에 `BACKUP_DIR` 문자열이 없는지 확인한다.
- 참고: `existing_backups` 는 `premigrate` 백업도 센다(backup.py:121-128). 그래서 매일 백업이 계속 실패해도 업그레이드 직후에는 "최근"으로 보인다. 정기 백업과 업그레이드 전 백업을 나눠 보이거나, 이름으로 걸러 낸다.
