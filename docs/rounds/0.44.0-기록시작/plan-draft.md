## 2. 항목

### A. 날마다 평가금액 기록 — 전문화 · 큼 · **지금 시작하지 않으면 그 전 기록은 영영 없다**

- **무엇**: 사람마다 하루 한 줄, 그날의 평가금액(기준통화)과 그 금액을 만든 보유 모습을 남긴다. 화면은 이번에 만들지 않는다(성과·낙폭은 쌓인 뒤).
- **왜**: 보유는 덮어쓰기이고 리밸런싱 기록은 사람이 누를 때만 남는다. 지난 평가금액을 되살릴 길이 없다(ROADMAP 2-1, §0 데이터 경계).
- **데이터**
  - 새 표 `portfolio_value_daily` — **사용자별**, **다시 만들 수 없다**.
  - 칸: `user_id`, `date`(기록한 날, 아래), `base_currency`, `total_value_base`, `stock_value_base`, `cash_value_base`,
    `positions`(JSON — 종목마다 수량·평단가·종가·종가 날짜·통화·기준통화 금액), `fx`(JSON — 쓴 환율), `recorded_at`. `(user_id, date)` 하나만.
  - `date` 는 **한국 날짜**로 기록 시각의 날짜. 기록은 UTC 23:20(한국 08:20, 미국 갱신 22:30 뒤 · 백업 23:30 앞) — 그 시각의 마지막 종가로 잰다.
    켤 때 오늘 줄이 없으면 따라잡기 갱신 뒤 한 번 더 시도. 같은 날 다시 돌면 덮어쓴다(같은 날 안에서만).
  - 누구: 승인된(`active`) 사람 중 보유수량이나 현금이 있는 사람. 0 이면 남기지 않는다.
  - 크기: 사람당 하루 1줄, `positions` 는 그 사람 종목 수만큼(종목 수 상한을 따른다). 1년 365줄.
  - 계산은 리밸런싱 현황과 같은 길(`rebalance.compute_positions`·`cash_amounts`·`fx.get_rates`) — 화면의 총액과 같은 숫자.
  - 외부 호출: 없음(저장된 종가·환율만). 사람 수만큼 늘어나는 것은 DB 읽기뿐.
- **마이그레이션 0014**: 표 하나 더하기. 내리기 = 표 지우기(쌓인 기록이 사라진다 → `DEPLOY.md` 9-2 에 적고, 내리기 전 백업). 앱이 0013 DB 로 떠도 깨지지 않게(0.42 와 같은 결).
- **보이는 곳**: 진단 화면(주인)에 "평가금액 기록: 마지막 날짜 · 사람 수 · 줄 수" 한 줄. 사용자에게는 리밸런싱 아래 "날마다 평가금액을 기록하고 있습니다(○일째)" 한 줄을 둘지 → **검토 의견을 받는다**.
- **방침**: 개인정보처리방침에 "날마다의 평가금액·보유 모습을 기록" 추가. 탈퇴하면 같이 지운다(지금 탈퇴가 지우는 표 목록에 더한다).

### B. 종합 신호등 정리 — 정교화 · 중간 · 화면만

- **무엇**(주인 말): "종합신호등에 비중에 의한 신호랑 기술적 지표에 의한 신호랑 구분이 잘 안 된다. 관망은 그냥 표시 안 하는 건 어때?"
- **지금**: PC 표의 "종합 신호등" 칸(`pages/Dashboard.tsx` 표)에 지표 신호(▲ 매수 / 관망 / ▼ 매도)와 비중 신호(◆ 매수 검토 / ◆ 매도 검토 / 정기 리뷰)가 이름 없이 한 줄로 붙는다.
  0.43 은 **카드 보기**만 "시그널 / 비중" 이름표로 갈랐고 표는 그대로다.
- **하려는 것**
  1. 표의 칸을 둘로: "시그널"(▲▼, 매도 조건도) · "비중"(◆ 과중·미달, 정기 리뷰). 칸 이름이 곧 이름표. 또는 한 칸 안에 카드와 같은 이름표 두 줄 — **검토 의견을 받는다**.
  2. **관망은 표시하지 않는다** — 표·카드·폰 목록 모두. 빈 자리는 비워 둘지 흐린 "—" 를 둘지 → 검토 의견. "갱신 필요"(시세 없음)는 그대로 보인다.
  3. 신호 요약 카드의 "관망 N" 숫자는 그대로(0.43 이 "누르지 않는 칸"으로 정함).
  4. 비중 배지 이름이 "매수 검토 / 매도 검토"라 지표 신호 "매수 / 매도"와 겹친다 → "채우기 / 줄이기" 같은 다른 말로 바꿀지 → **주인에게**(0.43 용어 사전 `docs/design/glossary.md` 와 부딪히는지 검토).

- **규제**: 색·말이 사라·팔아라로 더 세게 읽히지 않는지(관망을 지우면 매수·매도만 남아 화면이 더 "행동"처럼 보일 수 있다) → 검토자.
- **부딪히는 결정**: 디자인 1차 8-4(신호등과 사유 배지 한 줄), 디자인 2차 10-2(카드 이름표 세 줄, 관망 칸은 누르지 않음). 둘 다 표 칸을 가르는 것과는 부딪히지 않는다.
