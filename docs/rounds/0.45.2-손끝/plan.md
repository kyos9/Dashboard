초안 `plan-draft.md` 를 세 입장(`plan-dev.md`·`plan-review.md`·`plan-user.md`)이 한 번씩 보았다. **막음 0.** 고쳐야 함은 셋이 겹치는 것이 많았다 — 걱정마다 답을 적고 바뀐 계획을 아래에 둔다.
이견(입장끼리 갈린 것) 없음. 개발자가 "C 를 0.45.3 으로 나누는 길"을 냈지만 다른 둘은 크기를 걱정하지 않았고, 주인 요청이 "미리 완성"이라 **나누지 않는다**(C 는 다른 항목과 고치는 파일이 겹치지 않아, 막히면 C 만 따로 미룰 수 있다).

주인은 계획 승인을 맡겼다. 규제 영향 0, 마이그레이션 0, 저장되는 값 바뀜 0. API 는 필드 더하기(로그 줄의 `at`)와 **시각 문자열에 시간대 붙이기**(느린 요청) — 아래 B5.

## 항목 (바뀐 계획)

### A. 숫자 칸이 말한 뒤 — 중간
- A1 줄 자리: ① 팝업 머리 아래(팝업 밖이면 보이는 화면 위 + 8) ② 보이는 화면 아래 끝 − 8 — 치는 칸과 겹치지 않는 첫 곳. 줄이 떠 있는 동안 rAF 로 다시 잰다.
- A2 `minusHint` — 보유 수량 넷(일괄 수정·종목 추가·리밸런싱 표·카드) "보유 수량은 가진 전체 수량입니다(판 수량이 아닙니다)", 거래 수량 "팔았으면 ‘팔았다’를 고르세요". 화면 읽기 자리도 같은 글.
- A3 `onSaved(saved: string[])`(인자는 더하기 — 부르는 쪽이 안 써도 된다) · 닫힐 때 한 번 · "A·B 2종목을 저장했습니다" / "A 외 3종목을 저장했습니다". 두 화면, 수정 단추 아래 `role="status"`.
- A4 칸 아래 풀이 앞에 "새로 넣을 돈 ₩X 반영 — ".

**완료 조건**: A1 일괄 수정 팝업 360·390·1400 × 두 테마, 첫 줄·마지막 줄 보유 수량에 "-3" → 줄 ∩ (머리 h3·✕·치는 칸) = 0, 줄 전체가 보이는 화면 안 · `visualViewport` 목 시험(offsetTop 200 일 때 자리) · 리밸런싱 표 편집에서도 · 가로 넘침·콘솔 오류 0. A2 시험(붙는 칸·안 붙는 칸). A3 시험(한 번에 성공 · 일부 실패 뒤 다시 저장 → 합친 수 · 일부 저장 뒤 ✕). A4 360 에서 칸과 금액이 한 화면.
