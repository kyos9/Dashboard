# 0.45.2 C (차트를 손가락으로) — 검토자 판정

# 조건부 합격

이번 항목의 핵심인 손가락 동작은 직접 확인했다. 390과 360에서 0.3초 간격으로 60px·200px 떨어진 두 번째 탭이 그 날로 간다. 시작 커밋 빌드에서는 같은 탭이 무시됐다. ◀ ▶, 360×640 팝업 높이, 단추 줄 자리 잡기, aria-live 분리도 직접 돌려 맞았다.
다만 아래 셋은 고친 뒤 합친다. 넷째는 주인 확인으로 넘긴다.

**조건 (고쳐야 함)**
1. **PC 마우스로 천천히 끌면 차트는 밀리는데 "전체 보기"가 뜨지 않는다.** 원인은 `PriceChart.tsx:199` 의 `e.timeStamp - press.at < 240` 이 마우스에도 걸리는 것이다. 마우스에는 길게 누르기(추적 모드)가 없으므로 240ms 조건은 터치에만 걸어야 한다.
   재현은 두 가지다. 1400에서 1px/30ms 로 끌기, 또는 누르고 0.3초 쉰 뒤 5px/16ms 로 끌기. 둘 다 날짜 축 그림이 바뀌었고(밀림) `.chart-fit` visibility 는 `hidden` 이었다. 완료 조건 C3 "밀기 뒤에 뜬다"를 흔한 PC 끌기에서 못 지킨다.
2. **마우스로 끌다가 차트 밖에서 놓으면 다음 클릭 하나를 삼킨다.** 컨테이너에만 `pointerup` 을 달아서, 밖에서 놓으면 `press` 가 남는다. 그러면 다음 `pointerdown` 이 "두 번째 손가락"으로 처리된다(`:186`). 그 클릭은 탭이 아니게 되고, "전체 보기"가 근거 없이 뜬다.
   재현: 1400에서 세로로 600px 끌어 차트 밖에서 놓은 뒤 차트를 클릭하면 읽기 줄이 `2026-10-22 … (마지막 날 — …)` 그대로였다. 두 번째 클릭에서야 `2026-02-16` 으로 갔다. 고치는 길은 셋 중 하나다. 마우스에서 `pointerleave` 로 버리기, `window` 에서 `pointerup` 받기, `setPointerCapture`.
3. **직접 뮤테이션 4줄 중 1줄(의미 있는 것)이 살아남았다.** `:245` 를 `const base = current ??` 로 바꿔 ◀ ▶ 가 마우스로 가리키는 날에서 움직이게 해도 시험이 통과한다. "가리킴이 고른 날과 다른 상태에서 ◀"를 보는 시험이 없다. 손가락 기기에 남는 흉내 마우스가 이 경우다. 시험을 하나 더한다.

**주인 확인으로 넘김**
4. 완료 조건 "세로로 밀면 화면이 내려감(회귀)"은 **이번 빌드와 시작 빌드(d5bc80d) 모두 성립하지 않는다.** 그래서 회귀는 아니다. 계획 의견서(`plan-user.md:31`)가 "지금 된다"고 본 것이 틀렸다.
   라이브러리 설정이 `vertTouchDrag: true` 이고 `touchmove` 에서 `preventDefault` 한다. 그래서 차트 위 세로 밀기를 차트가 가져간다. 끝 보고에 "회귀 아님, 원래부터 안 됨, 실기기 확인·다음 후보"로 적어야 한다(status.md:54 의 총괄 기록과 같다).

## 참고 (막지 않음)

1. 360 팝업에서 읽기 줄은 "(마지막 날 — 차트를 누르면 그 날)"이 붙으면 두 줄, 빠지면 한 줄이다. 그래서 탭하거나 가리킴이 풀릴 때 차트가 약 20px 오르내린다(팝업 밀기 전후 `chart y 270.9 → 291.1`, `shots/popup360-l-0.png`·`-fit.png`). "전체 보기" 때문이 아니라 0.44 부터 있던 동작이다. 손가락 아래에서 차트가 움직이므로 다음 후보로 둔다.
2. "전체 보기"를 키보드로 누르면 단추가 숨으면서 포커스가 `BODY` 로 빠진다(크롬은 다음 Tab 이 이어지기는 한다). ◀ ▶ 에 쓴 생각을 여기에도 쓸 만하다.
3. 테마나 높이가 바뀌어 차트를 다시 만들면(`:107` 의존성) 고른 날의 십자선을 다시 놓지 않는다. 깃발(`movedOn`)도 그대로라 맞춰진 차트에 "전체 보기"가 남을 수 있다. 개발자 의견서가 짚은 것(`plan-dev.md:98,113`)인데 최종 계획 표에는 없었다.
4. CPU 부하가 12일 때 360-dark 의 빠른 밀기 한 번이 "전체 보기"를 못 띄웠다(240ms 창). 부하가 3일 때 다시 하면 네 조합 모두 통과했다. 느린 폰에서도 그럴 수 있는지 실기기 확인 목록에 둔다.
5. 팝업을 열 때 Playwright 의 흉내 마우스가 차트 위에 남으면 읽기 줄이 그 날을 보인다(`popup360-l-0.png` 의 02-10). 실기기에서는 아마 없겠지만 주인 확인 목록에 둔다.
