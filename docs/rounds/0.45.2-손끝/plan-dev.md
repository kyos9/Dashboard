**걱정**
1. **고쳐야 함 — A1 "따라간다"에는 듣는 곳이 셋 필요하다.** 지금은 `visualViewport` 의 resize·scroll 만 듣는다(`NumberInput.tsx:172-182`). 일괄 수정을 스크롤하는 것은 `.modal { overflow-y: auto }`(`index.css:2137`)이고, 표를 스크롤하는 것은 `.table-scroll { overflow-x: auto }`(`:1165`)다. 둘 다 scroll 이벤트가 위로 올라오지 않으므로 다음이 모두 있어야 한다.
   - `window.addEventListener('scroll', place, { capture: true, passive: true })`
   - `window` 의 resize
   - 지금의 vv resize·scroll

## C. 차트를 손가락으로

**찬성**: 원인과 방향이 맞다. 라이브러리는 터치와 마우스 이벤트만 듣고, pointer 이벤트는 듣지 않는다. `setPointerCapture`, `touch-action`, `stopPropagation` 도 쓰지 않는다(grep 0). 그래서 차트를 담은 div 에 pointer 리스너를 달아도 서로 겹치지 않는다. 라이브러리가 `preventDefault` 하는 것은 `touchmove`(`mjs:8187`)와 `touchend`(`:8256-8269`)뿐이다. 이것은 스크롤과 호환용 마우스·click 을 막을 뿐, pointer 이벤트는 그보다 먼저 온다. 그리고 차트 위에서는 세로로 끌어도 차트가 받는다(`vertTouchDrag: true`, `:9598`). 그래서 보통은 `pointercancel` 도 생기지 않는다. 길게 누르기도 확인했다.
- 240ms 를 누르고 있으면 추적 모드가 된다(`:8342`, `:9741-9745`).
- 추적 모드에서는 끌면 십자선이 움직인다(`:9786-9797`).
- 다음 탭이 오면 추적 모드가 풀린다(`trackingMode.exitMode = OnNextTap`, `:12494`).

그래서 C3 의 "길게 누른 채 밀면 날짜가 따라옵니다"는 사실이다. 손을 뗀 뒤 다음 밀기도 차트가 아니라 날짜를 움직인다는 것까지 적으면 된다.

**걱정**
1. **고쳐야 함 — C1: 길게 누른 뒤의 탭이 지워진다.** 이벤트는 `pointerup` → `touchend` 순으로 온다. 추적 모드가 켜진 상태에서 탭하면 일이 이렇게 흘러간다.
   1. 우리가 `pointerup` 에서 십자선과 `pointed` 를 놓는다.
   2. 이어 라이브러리의 `touchend` 가 `_tryExitTrackingMode` 를 부른다. 이것이 `clearCurrentPosition()` 을 부른다(`:10067-10071`).
   3. 그런데 이것은 `crosshairMoved(null)` 을 **쏜다**(`:7099-7105`, skipEvent 없음).
   4. 그러면 `onMove`(`PriceChart.tsx:155`)가 `pointed=null` 로 되돌린다.

   지금 구독 방식이 맞는 것은 라이브러리가 지운 **뒤에** click 을 쏘기 때문이다(`:8239` → `:8252`). → 탭 처리를 `setTimeout(0)` 으로 `touchend` 뒤로 미룬다. 시험에 "추적 모드 뒤 탭"을 넣는다.
2. **고쳐야 함 — C1 의 판정이 빠뜨린 것들.**
   - `pointerId` 를 맞춘다.
   - 두 번째 손가락이 닿으면(벌리기) 탭을 취소한다.
   - `pointercancel` 에서 취소한다.
   - 마우스는 `button === 0` 일 때만 받는다.
   - 가격 축(x > `timeScale().width()`)과 날짜 축(y > `paneSize().height`)에서 누른 것은 버린다. 지금 click 은 축에서 오지 않는데, div 단위 리스너는 축까지 받는다.
   - x 는 컨테이너의 left 에서 잰다(왼쪽 가격 축이 없어서 0 이다). 날은 `coordinateToLogical` → `series.dataByIndex(Math.round(l), NearestLeft)` 로 찾는다. 오른쪽 빈 칸은 지금과 같게 마지막 날로 간다.
   - 아이폰은 두 번 탭해 키우기 때문에 두 번째 탭의 이벤트를 늦추거나 삼킨다(`mjs:8033-8038` 주석). 컨테이너에 `touch-action: manipulation` 을 준다. 실기기는 주인 확인 목록에 넣는다.
3. **고쳐야 함 — C2: 지금 "가리킨 날"은 차트를 떠나면 지워진다.** ◀ 를 누르러 마우스가 차트를 나가면 두 가지가 일어난다.
   - 라이브러리가 `mouseLeave` 에서 십자선을 지운다(`:9748-9755`). 그러면 `crosshairMove(null)` 이 와서 `pointed=null` 이 된다.
   - 그래서 ◀ 가 늘 **마지막 날**에서 움직인다.

   → "고른 날"(탭·◀▶)과 "가리키는 날"(마우스를 올린 동안)을 상태 둘로 나눈다. 차트를 떠나면 고른 날로 돌아가게 한다. 이것은 지금의 "떠나면 마지막 날"(`:144-147` 주석)을 바꾸는 일이니 계획에 적는다.
   - 차트를 다시 만들 때(테마나 높이, `:107`)는 고른 날에 십자선을 다시 놓는다.
   - 키운 상태에서 화면 밖 날로 가면 `scrollToPosition`/`setVisibleLogicalRange` 로 따라갈지 정한다.
4. **고쳐야 함 — C2 의 단추가 폰 팝업의 높이를 넘긴다.** 0.45.0 C 는 360×640 차트 팝업에서 날짜 축이 첫 화면 안에 들도록 높이를 300/380 으로 맞췄다(`ChartModal.tsx:111-114`). 읽기 줄 옆에 44px 단추 둘이 들어가고 줄이 두 줄이 되면 다시 밀려난다. 완료 조건에 "360×640 팝업에서 날짜 축이 첫 화면 안"을 다시 넣고, 필요하면 높이를 줄인다.
5. **고쳐야 함 — C3: 범위 이벤트만으로는 "사람이 움직였다"를 가릴 수 없다.**
   - 범위가 실제로 바뀌면 이 이벤트는 언제나 불린다(`mjs:6654-6663`). 다음 경우가 다 해당한다.
     - `setData`
     - `fitContent` — 그 자리에서 바뀌지 않는다. 다음 그림에서 무효화로 적용된다(`:7208-7212`, `:11164-11166`)
     - 폭이 바뀔 때 — `lockVisibleTimeRangeOnResize: false`(`:12425`, `:6141`). 팝업이 열리면서 `ResizeObserver`(`PriceChart.tsx:105`)가 돌고, 폰을 돌려도 돈다
     - 손을 뗀 뒤의 관성 스크롤 — `kineticScroll.touch: true`, `:12490-12493`
   - 그래서 "fitContent 전후로 깃발 세우기"는 늦게 오는 이벤트를 놓친다.
   - → **사람의 입력으로 거른다.** 다음 셋 중 하나가 있으면 "움직였다"로 본다.
     - 컨테이너에서 5px 넘게 끈 pointer — 추적 모드가 아닐 때
     - `wheel`
     - 두 손가락
   - 범위 이벤트는 이 깃발이 선 뒤에만 단추를 띄운다. 그러면 길게 눌러 십자선을 끌 때는 범위가 바뀌지 않아 뜨지 않는다.
   - 다음 때는 단추와 깃발을 내린다. "전체 보기"를 눌렀을 때, `history` 가 바뀌었을 때(`:141`), 차트를 다시 만들었을 때.
   - 시험에서 범위를 비교할 때는 한 그림 뒤를 기다려야 한다.

**제안**
- C1 은 `setTimeout(0)` 지연, 축 거르기, `touch-action: manipulation` 까지 넣어 50줄 안팎이다.
- C3 의 더 작은 길: 범위 구독 없이 "사람이 끌거나 휠을 돌리거나 벌렸다"만으로 단추를 띄운다. `subscribeVisibleLogicalRangeChange` 를 목 다섯 개에 더할 필요가 없어진다. 목은 `PriceChart.markers`·`ChartModal`·`HistoryChart`·`FundamentalsPage`·`backToClose.modals` 시험의 다섯이다. 이 목들에는 지금 `timeScale: () => ({ fitContent })` 뿐이다. `coordinateToLogical`·`width` 와 `paneSize` 는 어느 길이든 더해야 한다.
- jsdom 30 에는 `PointerEvent` 가 있다. 그래서 `fireEvent.pointerDown/Up` 에 `clientX` 와 `pointerId` 를 실어 시험할 수 있다.

## 크기·호환

- 항목은 셋이지만 작은 항목은 열셋이다. 위험은 A1 과 C1 에 몰려 있고, 둘 다 아이폰 실기기 확인이 남는다. "중간"의 위쪽 끝이다. 나눈다면 **C 를 0.45.3 으로** 미는 것이 가장 깔끔하다. C 는 서버 변경이 없고, 다른 항목과 같이 고치는 파일도 없다.
- 호환: 새 서버와 옛 화면, 새 화면과 옛 서버 모두 더하기만 한다(B5 의 `at`·`utc_offset_minutes`, 느린 요청 시각의 꼬리). 마이그레이션은 0 이다. B3 은 경고 시점을 앞당기지만 아직 배포 전이라 문제없다.
