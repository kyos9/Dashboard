## D — 이름표 단추 "▾"(44px)·기준일은 펼친 풀이 맨 위·"✓ 충족 · 이름 : 풀이"·카드에서는 끔

- **개발자 · 풀림(막음)** — 칩 줄은 360 에서 이미 두 줄(51px)이라 44px 단추가 줄 높이를 늘리지 않는다. 이름표를 테두리·`padding 0 10px`·"▾" 단추로 끼워 15종목 접힌 상태를 재면 날짜 축이 **전과 같다**(604–637 → 604–637, 매도 줄 있는 삼성전자우·SK하이닉스 633, 가장 긴 TIGER·東京海上 637). 카드는 속성으로 꺼서 높이 그대로.
- **개발자 · 고쳐야 함 — "차트를 단추 높이만큼 더 낮춘다"는 틀린 처방이고, 진짜 위험은 이름표 칸 폭이다.** 칸은 `max-content`(index.css:1451)라 단추가 칸을 넓힌다: 매수만 69→102px, 매도 줄 있으면 100→133px. 칩이 세 줄로 넘어가는 문턱을 재 보니(칸 폭 328) 매수 칩이 가장 넓을 때(84·85·67·97, TIGER) **~134–139px**, 매도 줄 날(AAPL) ~140–149px. 매도 줄 날은 여유가 **약 6px** 이고, 넘으면 +27px → 633+27 = 660 > 640. 폰 글꼴(사파리·삼성)이 크롬 리눅스보다 조금만 넓어도 넘는다. → 차트는 낮추지 않는다(316/256 그대로). 대신 **이름표 단추 폭 상한**을 둔다: 두 줄 이름표("매도 조건 (참고)" / "1/3 ▾", 칸 66px, 끼워 보니 축 그대로) 또는 안쪽 여백 6px 이하. 완료 조건에 "매도 줄 날 이름표 칸 ≤ 120px" 를 적는다.
- **사용자 · 풀림** — 기준일이 이름표 옆이 아니라 펼친 풀이 맨 위라 접힌 상태 폭에 들지 않는다(605→688 문제 없음).
- **사용자·검토자 · 고쳐야 함 — 풀이 꼴.** (1) 예시 "종가가 MA20 아래**일 때**"는 서버 문자열 뒤에 화면이 "일 때"를 붙이는 것인데, 매도 조건 "ADX 가 5거래일 전보다 **큼**"(signal_rules.py:318)은 "큼일 때"가 된다. 붙이지 않거나 "조건:"을 앞에 둔다. (2) "✗ 미충족"의 ✗ 는 칩의 미충족 표시 "·"(display.ts:336)와 다르고, 바로 위 닫기 "✕"(용어집 :58)와 닮았다. `conditionMark` 의 기호·낱말("· 미충족", "? 판정 불가")을 그대로 쓴다.
- **검토자 · 참고** — 펼친 풀이의 "10-23 기준"과 읽기 줄의 "2026-10-23"이 한 화면에 섞인다(0.45.2 거슬림과 같은 꼴). `indicators.date` 가 null 이면 기준일 줄을 뺀다고 적는다. "▾"는 `aria-hidden`, 이름은 "매수 조건 2/4"(aria-expanded 가 상태를 말한다). 두 줄을 같이 펼칠 수 있는지 한 줄만인지 적는다.

## C — 신호 화면 풀이 이음표 전부(범례 둘째 문단·읽기 줄 풀이·칩 title)

- **사용자·검토자 · 풀림(범위)** — 사용자가 본 세 곳이 들어갔다.
- **개발자 · 풀림 — 읽기 줄 길이** — "—"→"·"는 글자 수가 같고 더 좁다. 읽기 줄은 `min-height: 2줄`(index.css)이라 360 에서 두 줄(41px) 그대로, 긴 풀이 "(▶ 나 오른쪽 끝을 누르면 마지막 날)"는 손대지 않는다. 줄 수 바뀜 없음.
- **검토자 · 고쳐야 함 — 완료 조건 "이음표 0" grep 범위가 정해지지 않았다.** 같은 신호 화면에 남는 것: 표 칸 칩 title `label — detail · word`(Dashboard.tsx:171·1301), "— 기본 기준과 같습니다"(:900), 팝업 "— 고른 기간보다 짧습니다"(ChartModal.tsx:80·83), 범례 `STREAK_HINT`(PriceChart.tsx:447), 서버 풀이 안의 "-DI > +DI — 하락 방향이 우위"(칩 title 에도 그대로 나온다 — D 처럼 화면에서 ", "로). 넣을 곳·뺄 곳을 목록으로 적는다. **B 의 새 배지 풀이 "비중 미달 — 목표보다 밴드 넘게 낮음"이 C 를 다시 어긴다** → "비중 미달(목표보다 밴드 넘게 낮음)".

## A — 칩 모양·아래 칩 줄 같이·`weightSide` 한 곳

- **검토자 · 풀림** — 테두리·44px·`active`·aria-pressed 로 용어집 :65 와 맞는다. 정렬 없음.
- **개발자 · 풀림** — `weightSide` 하나를 세기·거르기·넘어오기(`matchesQuick`)가 쓰면 "칩 수 ≠ 걸러진 수"가 안 생긴다.
- **사용자·개발자 · 고쳐야 함 — 아래 칩 줄에 칩 둘을 더하면 폰에서 줄이 하나 는다.** 360: 칩 줄 96→148px(두 줄→세 줄), 위 요약 27→44px 까지 합쳐 **첫 카드 위 끝 556→624**(640 화면에 16px 만 남음, 주인·지인 같음). 390: 537→606. 대신 **아래 "◆ 비중조절" 칩 하나를 켜진 꼴로 두고 이름을 "비중조절 · 초과 2"로 바꾸면** 줄이 96px 그대로다(끼워 잼). 그러면 남는 것은 위 요약 +17px 뿐.

## B — 밴드 "± z%p"·배지 풀이 낱말

- **사용자 · 풀림** — 밴드가 보여 "왜 이 종목만?"이 풀린다.
- **사용자·개발자 · 참고 — 360 카드 한 줄에 안 든다.** "◆ 비중 초과" + "지금 35.3% · 목표 6% ± 5%p" = 226px, 자리 217px → 숫자 묶음이 통째로 다음 줄(+23px, 비중 줄 있는 카드 3장). 390 은 한 줄(247px). 꺾임은 허용(초안 완료 조건)이니, 숫자 묶음을 nowrap 으로 두어 "± 5%p"만 떨어지지 않게 하고 완료 조건에 "360 은 두 줄"로 적는다. 목표·밴드가 소수일 때 자릿수(`num(…,0)`, 12.5→13)도 같이.
- 배지 낱말의 "—"는 위 C 에 적었다.

## E — 짧은 글자·nowrap

- **개발자·사용자 · 풀림** — "▲ 매수 · ▼ 매도(참고)"를 통째로 nowrap 하면 말 가운데서 안 꺾이고, 풀이 대신 그 자리에 오면 두 줄 안이다. "줄 끝"이 **풀이를 대신하는지 뒤에 붙는지** 적는다(뒤에 붙이면 360 에서 세 줄).
